# useDebugValue
useDebugValue는 React DevTools에서 커스텀 Hook에 라벨을 추가할 수 있게 해주는 React Hook
```useDebugValue(value, format?)```

## Reference
커스텀 Hook의 최상위 에서 useDebugValue를 호출하면, 디버그값을 나타낼 수 있다.
```javascript
function useOnlineStatus() {
  useDebugValue(isOnline ? 'Online' : 'Offline');
}
```

## Parameters
- ```value``` : React DevTools에서 표시할 값. 모든 타입 가능
- optional ```format?``` : - 포멧팅 함수, value를 인자로 받아 포멧된 값 반환

## Returns
- useDebugValue 는 값을 반환하지 않음

## Usage
### 커스텀 Hook에 라벨 추가하기
```javascript
function useOnlineStatus() {
  useDebugValue(isOnline ? 'Online' : 'Offline');
}
```
- 커스텀 훅 최상위에서 useDebugValue 호출
- useOnlineStatus를 사용하는 컴포넌트 검사시 ```OnlineStatus: "Online"``` 확인 가능
<br>
[예시](https://react.dev/reference/react/useDebugValue#adding-a-label-to-a-custom-hook)

### 디버그값 포멧팅
```javascript
useDebugValue(date, date => date.toDateString());
```
- 포멧팅 함수는 디버그값을 인자로 받아 나타낼 값을 번환
- 컴포넌트를 검사할 때 반환값이 React DevTools에 나타난다

# useDeferredValue
useDeferredValue는 UI의 일부 업데이트를 지연시켜주는 React Hook
```javascript
const deferredValue = useDeferredValue(value)
```

## Reference
```useDeferredValue(value, initialValue?)```
```javascript
function SearchPage() {
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);
  // ...
}
```
컴포넌트 최상위에서 useDeferredValue를 호출하여 해당 값의 지연된 버전을 얻을 수 있음

## Parameters
- ```value``` : 지연시키고 싶은 값. 모든 타입 가능
- optional ```initialValue?``` : 컴포넌트 초기 렌더링시 이전값이 없으므로 사용할 값

## Returns
- 초기 렌더링시 : ```initialValue``` 가 있으면 그 값, 없을 시 전달한 ```value```
- 업데이트시 : 이전 값을 사용해 리렌더링, 이후 백그라운드에서 새 값을 사용하여 리렌더링

## Caveats
- 업데이트가 Transition 안에서 발생한 경우
  - 이미 업데이트가 지연되고 있기 때문에 useDeferredValue는 항상 새 값을 반환
- useDeferredValue 에 전달하는 값은 원시값 이거나 렌더링 외부에서 생성된 객체여야함
  - 렌더링중 새 객체를 전달하면 매 렌더마다 다른 값으로 인식되어 불필요한 백그라운드 렌더링 발생
- useDeferredValue 가 다른 값을 받을때
  - 현재 렌더링과 별도로 새 값을 사용한 리렌더링을 백그라운드에 예약
  - 값이 도중에 업데이트되면 백그라운드 리렌더링을 다시 시작
- useDefferredValue는 ```<Suspense>``` 랑 통합되어 있음
  - 백그라운드 업데이트가 새로운 값에 의해 지연될때, fallback 을 보여주지 않고 이전 값을 보여줌
- useDeferredValue 자체는 네트워크 요청을 줄이지 않음
- 고정된 지연시간은 없음
- 백그라운드 렌더링이 커밋되기 이전에는 Effect를 실행하지 않음

## Usage
### 최신 컨텐츠가 로딩되는 동안 이전 콘텐츠를 표시
```javascript
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);
  return (
    <>
      <label>
        Search albums:
        <input value={query} onChange={e => setQuery(e.target.value)} />
      </label>
      <Suspense fallback={<h2>Loading...</h2>}>
        <SearchResults query={deferredQuery} />
      </Suspense>
    </>
  );
```
- 입력값은 즉시 업데이트
- 결과는 fallback을 보여주지 않고 이전 결과를 유지하다 새 결과로 업데이트


### 오래된 컨텐츠임을 나타내기
```javascript
const isStale = query !== deferredQuery;

<div style={{ opacity: isStale ? 0.5 : 1 }}>
  <SearchResults query={deferredQuery} />
</div>
```
- deferred 값으로 이전 결과를 흐리게 만들어 사용자에게 나타낼 수 있음

### UI 일부분 리렌더링 지연하기 (최적화)
```javascript
const SlowList = memo(function SlowList({ text }) {
  // ...
});
```
```javascript
const [text, setText] = useState('');
  const deferredText = useDeferredValue(text);
  return (
    <>
      <input value={text} onChange={e => setText(e.target.value)} />
      <SlowList text={deferredText} />
    </>
  );


```
- useDeferredValue를 사용하여 이전 값(props) 유지
- memo 로 리렌더링 방지


# useEffect
useEffect는 컴포넌트를 외부시스템과 동기화 시켜주는 React Hook
```useEffect(setup, dependencies?)```

## Parameters
- setup
  - Effect의 로직을 담고있는 함수
  - 선택적으로 cleanup 함수를 반환
  - 컴포넌트가 커밋될 때 react가 setup 함수를 실행
  - 의존성이 변경된 후에는 이전 값으로 cleanup 함수 실행 -> 새로운 값으로 setup 함수 실행
  - 컴포넌트가 DOM에서 제거되면 cleanup 함수 실행
- optional dependencies? (의존성) 
  - setup 코드 안에서 참조되는 모든 reactive 값(props, state, 컴포너트 안의 모든 변수와 함수) 의 리스트
  - 고정된 개수를 가져야함
  - React에서 각 의존성을 이전 값과 object.is로 비교
  - 생략시 모든 커밋 이후마다 Effect가 실행
 
## Returns
- undefined를 반환

## Caveats
- 컴포넌트 최상위나 Custom Hook 안에서만 호출 가능 ( 반복문, 조건문 X)
- 외부 시스템과 동기화하려는게 아니면 필요하지 않음
- Strict Mode 가 켜져있을시 cleanup 로직이 setup 로직을 되돌리는지 검증하기 위한 테스트를 개발 환경에서 실행
- 컴포넌트 안에서 선언된 객체나 함수가 의존성에 포함되면 불필요한 Effect가 실행될 수 있음
- Effect가 interaction에 의해 발생하는게 아니라면 브라우저가 Effect보다 새 화면을 먼저 보여줌
  - Effect가 시작적인 작업을 하거나 깜빡임등이 발생하면 useLayoutEffect를 사용
- Effect가 interaction에 의해 발생했다면 브라우저가 새 화면을 보여주기 이전에 Effect를 실행할 수 있음
  - ```alert()``` 처럼 새 화면이 나오기 전에 작업을 미뤄야 하면 ```setTimeout``` 을 사용
  - Effect의 state 업데이트 이전에 새 화면을 보여줄수도 있음 -> useLayoutEffect 사용
 - Effect는 클라이언트에서만 실행됨

## Usage
### Connecting to an external sysytem
```javascript
function ChatRoom({ roomId }) {
  const [serverUrl, setServerUrl] = useState('https://localhost:1234');

  useEffect(() => {
  	const connection = createConnection(serverUrl, roomId);   // setup code
    connection.connect();      // setup code
  	return () => {
      connection.disconnect();   // cleanup code
  	};
  }, [serverUrl, roomId]);   // list of dependencies
  // ...
}
```
useEffect에 두 인자 전달:
1. 외부시스템과 연결하는 setup 함수 및 연결을 해제하는 cleanup 함수
2. dependency의 배열

React는 필요할때마다 setup, cleanup을 여러번 호출
1. 컴포넌트가 마운트 됐을때 setup code 실행
2. dependencies가 변경되었을때
  - 이전 props, state로 cleanup code 실행
  - 새로운 props, state로 setup code 실행
3. 컴포넌트가 언마운트 됐을때 cleanup code 실행

### Note
외부 시스템의 예시
- ```setInterval()```, ```clearInterval()``` 로 관리되는 타이머
- ```window.addEventListener()```, ```window.removeEventListener()``` 로 관리되는 이벤트
- ```animation.start()```, ```animation.reset()``` 같은 애니메이션 라이브러리 API

### Wrapping Effects in custom Hooks
```javascript
unction useChatRoom({ serverUrl, roomId }) {
  useEffect(() => {
    const options = {
      serverUrl: serverUrl,
      roomId: roomId
    };
    const connection = createConnection(options);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId, serverUrl]);
}
```
Effect를 자주 작성하게 되면 공통 로직을 커스텀 Hook으로 추출할 수 있음

### Controlling a non-React widget
컴포넌트의 prop이나 state에 맞춰 외부 시스템을 동기화하고 싶을때
```javascript
export default function Map({ zoomLevel }) {
  const containerRef = useRef(null);
  const mapRef = useRef(null);

  useEffect(() => {
    if (mapRef.current === null) {
      mapRef.current = new MapWidget(containerRef.current);
    }

    const map = mapRef.current;
    map.setZoom(zoomLevel);
  }, [zoomLevel]);

  return (
    <div
      style={{ width: 200, height: 200 }}
      ref={containerRef}
    />
  );
}
```
ex) React 없이 작성된 서드파티 지도 위젯이 있을때
- Effect를 사용해 위젯의 메서드를 호출하여 React 컴포넌트의 현재 state와 일치시킬 수 있음
- 이 Effect는 ```map-widget.js```에 정의된 ```MapWidget```클래스의 인스턴스를 생성
- ```Map``` 컴포넌트의 zoomLevel prop이 변경되면 Effect는 클래스 인스턴스의 setZoom()을 호출하여 동기화
- 이 예제에서 MapWidget 클래스는 wjsekfqkedms DOM 노드만 관리하기 때문에 cleanup 함수 필요 X

### Fetching data with Effects
```javascript
export default function Page() {
  const [person, setPerson] = useState('Alice');
  const [bio, setBio] = useState(null);

  useEffect(() => {
    let ignore = false;
    setBio(null);
    fetchBio(person).then(result => {
      if (!ignore) {
        setBio(result);
      }
    });
    return () => {
      ignore = true;
    };
  }, [person]);
```
- Effect를 사용해 컴포넌트의 데이터를 가져올 수 있음
- 프레임워크를 사용중이면 프레임워크의 fetching 메커니즘을 사용하는것이 효율적
- async / await 문법으로 작성 가능하지만 cleanup 함수 필요
- Effect 안에서 직접 데이터를 페칭하면 코드가 반복되고 최적화 추가가 어려움

### Specifying reactive dependencies
- Effect의 의존성을 "선택" 할수는 없음
- Effect 에서 사용되는 모든 반응형 값은 의존성으로 선언해야 함
- 빈 의존성 배열을 가진 Effect는 props나 state가 변경되어도 실행되지 않음

### Updating state based on previous state from an Effect
Effect 안에서 이전 state를 기반으로 state를 업데이트하면 생기는 문제
```javascript
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const intervalId = setInterval(() => {
      setCount(count + 1); // You want to increment the counter every second...
    }, 1000)
    return () => clearInterval(intervalId);
  }, [count]); // 🚩 ... but specifying `count` as a dependency always resets the interval.
  // ...
}
```
- count 를 의존성으로 하면 count가 바뀔때마다 Effect 실행
- ```count+1``` 대신 ```c => c + 1 ``` 형태의 state 업데이터 함수를 전달 -> count를 의존성에 포함할 필요 없음

### Removing unnecessary object and functing dependencies
의존성에 렌더링중 생성된 객체나 함수가 있으면 Effect가 필요 이상으로 실행될 수 있음
- 해당 객체 또는 함수를 Effect 내부에서 생성하는 방법으로 해결
- dependencies는 primitive 타입 위주로

### Reading the latest props and state from an Effect
Effect에서 최신 props 나 state를 읽고 싶지만 Effect를 실행시키고싶지는 않을떄
ex) ```url``` 이 바뀔 때만 페이지 방문을 기록하고 ```shoppingCart```만 바뀔 때는 기록하지 않고싶을때
```javascript
function Page({ url, shoppingCart }) {
  useEffect(() => {
    logVisit(url, shoppingCart.length);
  }, [url, shoppingCart]); // ✅ All dependencies declared
  // ...
}
```
useEffectEvent Hook으로 Effect Event를 선언하고 shoppingCart를 읽는 코드를 안으로 옮긴다
```javascript
function Page({ url, shoppingCart }) {
  const onVisit = useEffectEvent(visitedUrl => {
    logVisit(visitedUrl, shoppingCart.length)
  });

  useEffect(() => {
    onVisit(url);
  }, [url]); // ✅ All dependencies declared
  // ...
}
```
- Effect Event는 반응형이 아니므로 Effect의 의존성 배열에서 제외
- onVisit 에서 shoppingCart를 읽으므로 shoppingCart가 변경되어도 Effect 실행 X
Effet에서 값을 읽고만 싶으면 useEffectEvent로 분리

### Displaying different content on the server and the client 
서버와 클라이언트에서 다른 내용 표시
- 서버에서는 초기 HTML을 생성하기 위해 렌더링
- 클라이언트에서 HTML에 이벤트 헨들러를 연결하기 위해 렌더링 코드 재실행
```javascript
function MyComponent() {
  const [didMount, setDidMount] = useState(false);

  useEffect(() => {
    setDidMount(true);
  }, []);

  if (didMount) {
    // ... return client-only JSX ...
  }  else {
    // ... return initial JSX ...
  }
}
```
ex) 클라이언트에서 서버와 다른 내용을 보여주어야할 떄
- didMount 상태 사용
- 컴포넌트가 마운트되면 useEffect가 didMount를 true로 설정
- 앱이 로딩되는 동안 사용자는 초기 렌더 결과를 보게 됨
- hydration 완료시 Effect실행, didMount가 true 되면서 리렌더링
- 화면은 클라이언트 전용 렌더링 결과
- Effect는 서버에서 실행 X -> 초기 렌더링 시점에는 didMount 가 false
- 느린 네트워크 환경에서 사용자가 초기 컨텐츠를 오랜시간 보게 될 수 있음

## Troubleshooting
### My Effect runs twice when the component mounts
- Strit Mode 가 켜져있는 경우 개발 환경에서 React가 실제 setup을 실행하기 전 setup과 cleanup을 한번 실행
- 문제가 발생한다면 cleanup 함수에 로직이 빠져있다는 의미

### My Effect runs after every re-render
- 의존성 배열을 빠뜨렸는지 확인
- 의존성을 콘솔에 출력해서 디버깅
- 최후의 수단으로 useMemo / useCallback

### My Effect keeps re-running in an infinite cycle
Effect가 무한 루프에 빠질시 다음 조건이 반드시 동시에 성립
1. Effect가 state를 업데이트중
2. 그 state 변경이 리렌더링을 발생, Effect의 의존성을 변경

#### 확인 할 것
- Effect가 외부 시스템과 동기화 중인지 확인
  - 외부 시스템이 없다면 Effect를 제거하는게 더 단순할 수 있음
- 렌더링에 사용되지 않는 데이터를 추적할 경우 리렌더링을 발생시키지 않는 ref가 적합할 수 있음
- state 업데이트가 Effect의 의존성을 변경하고 있는지

### My cleanup logic runs even though my component didn’t unmount 
- cleanup 함수는 언마운트 됐을때만이 아니라 의존성이 변경되기 전에도 실행
- 개발환경에서는 컴포넌트가 마운트된 직후 setup과 cleanup이 실행
