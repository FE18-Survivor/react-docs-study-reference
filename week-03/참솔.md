## [useDebugValue](https://react.dev/reference/react/useDebugValue)

- React DevTools에서 custom hook에 label을 추가해 주는 hook
- Shared libraries에 포함된 custom hook 또는 내부 data 구조가 복잡해서 inspect 하기 어려운 custom hook에만 사용하면 된다.

### Reference

- `useDebugValue(value, format?)`
- Parameters
  - `value` : React DevTools에 표시할 값
  - `format` (optional) : React DevTools에서 inspect 된 component에 보여줄 값을 formatting 하는 함수 (값이 없으면 `value`를 그대로 표시)
    - React DevTools에서 component를 inspect 할 때마다 호출됨
    - 비싼 formatting logic이 component가 inspect 되기 전까지 실행되지 않도록 만들 수 있음
- Returns : void

### Usage

#### Adding a label to a custom hook

```javascript
import { useDebugValue } from "react";

function useOnlineStatus() {
  // ...
  useDebugValue(isOnline ? "Online" : "Offline");
  // ...
}
```

<img src="https://react.dev/images/docs/react-devtools-usedebugvalue.png" width="500" />

#### Deferring formatting of a debug value

```javascript
useDebugValue(date, (date) => date.toDateString());
```

## [useDeferredValue](https://react.dev/reference/react/useDeferredValue)

- UI 갱신을 부분적으로 지연(defer)시키는 hook

### Reference

- `useDeferredValue(value, initialValue?)`
- Parameters
  - `value` : 지연시키고자 하는 값
  - `initialValue` (optional) : 첫 번째 render에서 반환되는 값
    - `initialValue`가 없으면 첫 번째 render 에서는 지연시키지 않음
- Returns
  - 첫 번째 render에서 `initialValue` 또는 `value`와 동일한 값 반환
  - Updating 동안에는 먼저 old value로 re-render를 시도하고 new value를 받으면 background에서 다시 re-render 시도
    - Updating : `useDeferredValue`로 전달되는 `value`가 변경되는 것
- Caveats
  - Transition 안에서 update 되는 경우, `useDeferredValue`는 항상 new value를 반환하고 deferred render를 발생시키지 않음
    - Transition : `useTransition`의 `startTransition`을 호출하여 낮은 우선순위로 함수를 실행시키는 것
    - 이 경우, transition에 의해 이미 re-render가 지연 처리되므로 `useDeferredValue`에서 중복으로 지연 처리할 필요가 없음
    - 따라서, transition 내부에서 update가 trigger 되면 `useDeferredValue`는 즉시 new value를 반환하고 background re-render를 발생시키지 않음
  - `value`는 primitive values 또는 **rendering 외부에서 생성된 objects** 여야 함
    - Rendering 중에 생성되는 object들은 `Object.is`로 비교할 때 항상 다른 값으로 평가
    - 따라서, 모든 re-render 마다 update를 발생시켜 불필요한 background re-render를 유발함
  - `useDeferredValue`에 다른 값이 전달되는 경우, new value로 background re-render를 schedule 함
    - Background re-render는 **중단 가능(interruptible)**함
    - React는 `value`가 변경될 때마다 background re-render가 처음부터 다시 시작
    - e.g. 사용자가 deferred re-render 보다 빠르게 typing 한다면 typing을 멈췄을 때 한 번만 re-render 된 UI가 반영됨
  - `useDeferredValue`는 `<Suspense>`와 통합되어 있음
    - Background update가 UI를 지연시키는 new value에 의해 발생하는 경우 fallback UI를 보여주지 않고 old value로 UI가 render 됨 (previous UI가 존재하기 때문)
    - `<Suspense>`의 `fallback` UI는 최초 render 에서만 사용됨
  - `useDeferredValue`는 fixed delay를 사용하지 않음 (e.g. `setTimeout`)
    - React는 original re-render가 완료된 후 즉시 background re-render를 실행함
    - Typing 등 event에 의해 update가 발생하면 background re-render를 중단(interrupt)시키고 event에 의한 re-render를 우선 실행
    - 즉, **고정된 delay가 아닌 우선순위(priority)에 의해 지연되는 방식**
  - `useDeferredValue`에 의해 발생한 background re-render는 screen에 반영(committed) 되기 전까지 Effect를 trigger 하지 않음. **Effect는 background re-render가 완료된 이후 실행됨**

### Usage

#### Showing stale content while fresh content is loading

- 아래 코드는 state가 변경될 때마다 `<Suspense>`의 `fallback` UI가 표시되어 사용자가 typing 할 때마다 화면이 깜빡거리게 됨
  ```javascript
  export default function App() {
    const [query, setQuery] = useState("");
    return (
      <>
        <label>
          Search albums:
          <input value={query} onChange={(e) => setQuery(e.target.value)} />
        </label>
        <Suspense fallback={<h2>Loading...</h2>}>
          <SearchResults query={query} />
        </Suspense>
      </>
    );
  }
  ```
- Deferred value(`deferredQuery`)를 사용하면 `query`가 변경되어도 `deferredQuery`가 처음에는 old value를 반환해서 UI를 그리기 때문에 `fallback` UI 대신 이전 data로 구성된 UI가 표시되고, background re-render가 완료되면 new value가 UI에 반영됨
  ```javascript
  export default function App() {
    const [query, setQuery] = useState("");
    const deferredQuery = useDeferredValue(query);
    return (
      <>
        <label>
          Search albums:
          <input value={query} onChange={(e) => setQuery(e.target.value)} />
        </label>
        <Suspense fallback={<h2>Loading...</h2>}>
          <SearchResults query={deferredQuery} />
        </Suspense>
      </>
    );
  }
  ```

#### Indicating that the content is stale

- State(`query`)와 deferred value(`deferredQuery`)를 비교해서 loading 상태를 나타낼 수 있음
  ```javascript
  const isStale = query !== deferredQuery;
  <div style={{ opacity: isStale ? 0.5 : 1 }}>
    <SearchResults query={deferredQuery} />
  </div>;
  ```

#### Deferring re-rendering for a part of the UI

- UI 일부분이 re-render를 지연시켜서 다른 UI를 block하는 문제가 발생할 수 있음
  ```javascript
  function App() {
    const [text, setText] = useState("");
    return (
      <>
        <input value={text} onChange={(e) => setText(e.target.value)} />
        <SlowList text={text} />
      </>
    );
  }
  ```
- `memo()`를 사용해서 props가 동일할 때 re-render를 skip 할 수 있지만, 위와 같은 상황에서는 `text` prop이 게속 변경되므로 성능 문제가 해결되지 않음
- `useDeferredValue`를 사용하면 input을 갱신하는 작업의 우선순위를 높이고 result list(`SlowList`)를 갱신하는 작업의 우선순위는 낮출 수 있음

  ```javascript
  function App() {
    const [text, setText] = useState("");
    const deferredText = useDeferredValue(text);
    return (
      <>
        <input value={text} onChange={(e) => setText(e.target.value)} />
        <SlowList text={deferredText} />
      </>
    );
  }
  ```

  - `SlowList`는 `deferredText`를 사용하므로, `text`가 변경되어도 먼저 old value로 render한 뒤 내부적으로 background re-render가 완료된 이후 UI가 갱신됨
  - `SlowList`에 `memo()`가 사용되었으므로 old value를 사용할 때는 props이 동일하여 re-render가 발생하지 않음

- 이것은 `SlowList`의 re-rendering을 빠르게 만들어 주지는 않지만, **keystrokes를 block 하지 않도록 React가 re-rendering을 deprioritize 하도록 알려줌**

#### How is deferring a value different from debouncing and throttling?

- 이전에는 t yping 기반 시나리오에서 성능 최적화를 위해 debouncing과 throttling이 자주 사용됨
- **`useDeferredValue`는 React에 깊게 통합되어 있고 사용자 device에 따라 적용 가능하므로 rendering 최적화에 더 적합함**
- Debouncing 또는 throttling과 다른 점
  - Fixed delay를 사용하지 않기 때문에 사용자 device에 따라 rendering 성능이 조절됨
    - Device 성능이 빠르면 deferred re-render가 빠르게 처리되어 거의 알아채지 못함
    - Device 성능이 느리면 적절한 수준으로 지연됨(lag behind)
  - Deferred re-render가 중단 가능(interruptible)하므로, re-render가 시작된 상태에서도 interaction을 block 하지 않음
- 최적화하려는 작업이 rendering 중간에 실행되지 않는다면 debouncing과 throttling이 유용함
  - Network requests 전송 횟수 조절 등
