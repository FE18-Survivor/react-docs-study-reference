## [useDebugValue](https://react.dev/reference/react/useDebugValue)

- React DevTools에서 custom hook에 label을 추가해 주는 hook
- Shared libraries에 포함된 custom hook 또는 내부 data 구조가 복잡해서 inspect 하기 어려운 custom hook에만 사용하면 된다.

### Reference

- `useDebugValue(value, format?)`
- Parameters
  - `value` : React DevTools에 표시할 값
  - `format` (optional) : React DevTools에서 inspect 된 component에 보여줄 값을 formatting 하는 함수 (값이 없으면 `value`를 그대로 표시)
    - React DevTools에서 component를 inspect 할 때마다 호출됨
    - 비싼 formatting logic이 component가 inspect 되기 전까지 실행되지 않도록 만들 수 있음
- Returns : void

### Usage

#### Adding a label to a custom hook

```javascript
import { useDebugValue } from "react";

function useOnlineStatus() {
  // ...
  useDebugValue(isOnline ? "Online" : "Offline");
  // ...
}
```

#### Deferring formatting of a debug value

```javascript
useDebugValue(date, (date) => date.toDateString());
```

## [useDeferredValue](https://react.dev/reference/react/useDeferredValue)

- UI 갱신을 부분적으로 지연(defer)시키는 hook

### Reference

- `useDeferredValue(value, initialValue?)`
- Parameters
  - `value` : 지연시키고자 하는 값
  - `initialValue` (optional) : 첫 번째 render에서 반환되는 값
    - `initialValue`가 없으면 첫 번째 render 에서는 지연시키지 않음
- Returns
  - 첫 번째 render에서 `initialValue` 또는 `value`와 동일한 값 반환
  - Updating 동안에는 먼저 old value로 re-render를 시도하고 new value를 받으면 background에서 다시 re-render 시도
    - Updating : `useDeferredValue`로 전달되는 `value`가 변경되는 것
- Caveats
  - Transition 안에서 update 되는 경우, `useDeferredValue`는 항상 new value를 반환하고 deferred render를 발생시키지 않음
    - Transition : `useTransition`의 `startTransition`을 호출하여 낮은 우선순위로 함수를 실행시키는 것
    - 이 경우, transition에 의해 이미 re-render가 지연 처리되므로 `useDeferredValue`에서 중복으로 지연 처리할 필요가 없음
    - 따라서, transition 내부에서 update가 trigger 되면 `useDeferredValue`는 즉시 new value를 반환하고 background re-render를 발생시키지 않음
  - `value`는 primitive values 또는 **rendering 외부에서 생성된 objects** 여야 함
    - Rendering 중에 생성되는 object들은 `Object.is`로 비교할 때 항상 다른 값으로 평가
    - 따라서, 모든 re-render 마다 update를 발생시켜 불필요한 background re-render를 유발함
  - `useDeferredValue`에 다른 값이 전달되는 경우, new value로 background re-render를 schedule 함
    - Background re-render는 **중단 가능(interruptible)**함
    - React는 `value`가 변경될 때마다 background re-render가 처음부터 다시 시작
    - e.g. 사용자가 deferred re-render 보다 빠르게 typing 한다면 typing을 멈췄을 때 한 번만 re-render 된 UI가 반영됨
  - `useDeferredValue`는 `<Suspense>`와 통합되어 있음
    - Background update가 UI를 지연시키는 new value에 의해 발생하는 경우 fallback UI를 보여주지 않고 old value로 UI가 render 됨 (previous UI가 존재하기 때문)
    - `<Suspense>`의 `fallback` UI는 최초 render 에서만 사용됨
  - `useDeferredValue`는 fixed delay를 사용하지 않음 (e.g. `setTimeout`)
    - React는 original re-render가 완료된 후 즉시 background re-render를 실행함
    - Typing 등 event에 의해 update가 발생하면 background re-render를 중단(interrupt)시키고 event에 의한 re-render를 우선 실행
    - 즉, **고정된 delay가 아닌 우선순위(priority)에 의해 지연되는 방식**
  - `useDeferredValue`에 의해 발생한 background re-render는 screen에 반영(committed) 되기 전까지 Effect를 trigger 하지 않음. **Effect는 background re-render가 완료된 이후 실행됨**

### Usage

#### Showing stale content while fresh content is loading

- 아래 코드는 state가 변경될 때마다 `<Suspense>`의 `fallback` UI가 표시되어 사용자가 typing 할 때마다 화면이 깜빡거리게 됨
  ```javascript
  export default function App() {
    const [query, setQuery] = useState("");
    return (
      <>
        <label>
          Search albums:
          <input value={query} onChange={(e) => setQuery(e.target.value)} />
        </label>
        <Suspense fallback={<h2>Loading...</h2>}>
          <SearchResults query={query} />
        </Suspense>
      </>
    );
  }
  ```
- Deferred value(`deferredQuery`)를 사용하면 `query`가 변경되어도 `deferredQuery`가 처음에는 old value를 반환해서 UI를 그리기 때문에 `fallback` UI 대신 이전 data로 구성된 UI가 표시되고, background re-render가 완료되면 new value가 UI에 반영됨
  ```javascript
  export default function App() {
    const [query, setQuery] = useState("");
    const deferredQuery = useDeferredValue(query);
    return (
      <>
        <label>
          Search albums:
          <input value={query} onChange={(e) => setQuery(e.target.value)} />
        </label>
        <Suspense fallback={<h2>Loading...</h2>}>
          <SearchResults query={deferredQuery} />
        </Suspense>
      </>
    );
  }
  ```

#### Indicating that the content is stale

- State(`query`)와 deferred value(`deferredQuery`)를 비교해서 loading 상태를 나타낼 수 있음
  ```javascript
  const isStale = query !== deferredQuery;
  <div style={{ opacity: isStale ? 0.5 : 1 }}>
    <SearchResults query={deferredQuery} />
  </div>;
  ```

#### Deferring re-rendering for a part of the UI

- UI 일부분이 re-render를 지연시켜서 다른 UI를 block하는 문제가 발생할 수 있음
  ```javascript
  function App() {
    const [text, setText] = useState("");
    return (
      <>
        <input value={text} onChange={(e) => setText(e.target.value)} />
        <SlowList text={text} />
      </>
    );
  }
  ```
- `memo()`를 사용해서 props가 동일할 때 re-render를 skip 할 수 있지만, 위와 같은 상황에서는 `text` prop이 게속 변경되므로 성능 문제가 해결되지 않음
- `useDeferredValue`를 사용하면 input을 갱신하는 작업의 우선순위를 높이고 result list(`SlowList`)를 갱신하는 작업의 우선순위는 낮출 수 있음

  ```javascript
  function App() {
    const [text, setText] = useState("");
    const deferredText = useDeferredValue(text);
    return (
      <>
        <input value={text} onChange={(e) => setText(e.target.value)} />
        <SlowList text={deferredText} />
      </>
    );
  }
  ```

  - `SlowList`는 `deferredText`를 사용하므로, `text`가 변경되어도 먼저 old value로 render한 뒤 내부적으로 background re-render가 완료된 이후 UI가 갱신됨
  - `SlowList`에 `memo()`가 사용되었으므로 old value를 사용할 때는 props이 동일하여 re-render가 발생하지 않음

- 이것은 `SlowList`의 re-rendering을 빠르게 만들어 주지는 않지만, **keystrokes를 block 하지 않도록 React가 re-rendering을 deprioritize 하도록 알려줌**

#### How is deferring a value different from debouncing and throttling?

- 이전에는 t yping 기반 시나리오에서 성능 최적화를 위해 debouncing과 throttling이 자주 사용됨
- **`useDeferredValue`는 React에 깊게 통합되어 있고 사용자 device에 따라 적용 가능하므로 rendering 최적화에 더 적합함**
- Debouncing 또는 throttling과 다른 점
  - Fixed delay를 사용하지 않기 때문에 사용자 device에 따라 rendering 성능이 조절됨
    - Device 성능이 빠르면 deferred re-render가 빠르게 처리되어 거의 알아채지 못함
    - Device 성능이 느리면 적절한 수준으로 지연됨(lag behind)
  - Deferred re-render가 중단 가능(interruptible)하므로, re-render가 시작된 상태에서도 interaction을 block 하지 않음
- 최적화하려는 작업이 rendering 중간에 실행되지 않는다면 debouncing과 throttling이 유용함
  - Network requests 전송 횟수 조절 등

## [useEffect](https://react.dev/reference/react/useEffect)

- Component를 external system과 동기화(synchronize) 하는 hook

### Reference

- `useEffect(setup, dependencies?)`
- Parameters
  - `setup` : Optional cleanup 함수를 반환하는 Effect logic 함수
    - Component가 commit 된 이후 실행
    - `dependencies`에 명시된 값이 변경되어 commit 될 때마다 old value로 cleanup 함수를 실행하고 new value로 `setup` 함수 실행
    - Component가 DOM에서 제거된 후 마지막 cleanup 함수 실행
  - `dependencies` (optional) : `setup` 함수 안에서 참조된 reactive values
    - Reactive values : props, state, component body에서 선언된 variables and functions
    - `dependencies` list는 고정된 갯수 items(constant number of items)을 갖는 inline array여야 함
    - List를 전달하지 않으면 component가 re-render -> commit 될 때마다 `setup` 함수 실행
    - 빈 배열(`[]`)을 전달하면 effect가 컴포넌트가 처음 마운트 될 때만 실행됨
    - 전달하지 않으면 매 렌더링
- Returns : `undefined`
- Caveats
  - External system과 동기화하는 목적이 아니라면 Effect가 필요 없음
  - Strict mode가 활성화되면 development mode에서 `setup` 및 cleanup 함수가 한번 더 실행되어 실행 중이던 setup을 중단
    - Strict mode에서 문제가 발생한다면 cleanup 함수를 구현
  - `dependencies`에 component 내부에서 정의된 객체 또는 함수가 있으면 Effect가 필요 이상으로 호출될 위험이 있으므로, 불필요한 객체 또는 함수를 제거
    - State update 및 non-reactive logic을 Effect 밖으로 추출
  - Effect가 click 등 user interaction에 의해 발생한 것이 아니라면, React는 Effect 실행 전에 browser가 updated screen을 paint 하도록 함
    - Effect 내부의 tooltip 위치 변경 등 시각적인 변화에 delay가 발생한다면 `useLayoutEffect`를 대신 사용
  - Effect가 user interaction에 의해 발생했다면, React는 browser가 updated screen을 paint 하기 전에 Effect를 실행시킴
    - Effect logic을 paint 이후 실행시키고 싶다면 `setTimeout` 사용 (e.g. `alert()` 호출)
  - Effect가 user interaction에 의해 발생했더라도, React는 Effect 내부에서 state update가 처리되기 전에 browser를 repaint 시킴
    - Browser가 screen을 reapint 시키지 않도록 막고 싶다면 `useLayoutEffect`를 대신 사용
  - Effect는 client 에서만 실행됨 (server rendering 중에는 실행되지 않음)

### Usage

#### Connecting to an external system

```javascript
function ChatRoom({ roomId }) {
  const [serverUrl, setServerUrl] = useState("https://localhost:1234");

  useEffect(() => {
    // Effect에서 connection 생성
    const connection = createConnection(serverUrl, roomId);
    connection.connect();

    // Cleanup function에서 disconnect
    return () => {
      connection.disconnect();
    };
  }, [serverUrl, roomId]);
  // ...
}
```

- External : Network, browser API, third-party library 등 compmonent가 화면에 나타나는 동안 연결된 상태를 유지해야 하는 것들
  - `setInterval()` 및 `clearInterval()`로 관리하는 timer
  - `window.addEventListener()` 및 `window.removeEventListener()`로 관리하는 event subscription
  - `animation.start()` 및 `animation.reset()`으로 관리하는 third-party animation library
- `useEffect`를 사용해서 component와 external system간에 연결 유지
- React는 `setup`과 cleanup 함수를 필요할 때 여러 번 호출하여 **Effect logic이 정확하게 구현되었는지 stress-test 진행**
  - Component가 mount 되었을 때 `setup` 함수 호출
  - Component commit 이후 `dependencies`가 변경되었을 때 cleanup -> `setup` 순서로 호출
  - Component가 unmount 되었을 때 마지막으로 반환된 cleanup 함수 호출
- 모든 Effect 들을 독립적인 process로 작성하고 한 번에 setup/cleanup cycle이 한 번 실행된다고 생각하기
  - Component의 mounting, updating, unmounting과는 관련 없음
  - Cleanup logic이 setup logic에 맞게 정확히 작성되었다면, setup 및 cleanup 함수가 여러 번 실행되어도 Effect logic은 문제 없음

#### Wrapping Effects in custom Hooks

```javascript
function useChatRoom({ serverUrl, roomId }) {
  useEffect(() => {
    const options = {
      serverUrl: serverUrl,
      roomId: roomId
    };
    const connection = createConnection(options);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId, serverUrl]);
}

function ChatRoom({ roomId }) {
  const [serverUrl, setServerUrl] = useState('https://localhost:1234');

  useChatRoom({
    roomId: roomId,
    serverUrl: serverUrl
  });
  // ...
```

- 자주 필요한 Effect는 custom hook으로 추출

#### Controlling a non-React widget

- External system을 component의 prop이나 state와 동기화

#### Fetching data with Effects

```javascript
export default function Page() {
  const [person, setPerson] = useState('Alice');
  const [bio, setBio] = useState(null);

  useEffect(() => {
    let ignore = false;
    setBio(null);
    fetchBio(person).then(result => {
      if (!ignore) {
        setBio(result);
      }
    });

    // Cleanup 함수에서 이전 fetching result를 무시하도록 flag 설정
    return () => {
      ignore = true;
    };
  }, [person]);

  // ...
```

- Effect를 data fetching에 사용할 수 있음
- Framework를 사용한다면 framework의 data fetching mechanism을 사용하는게 더 좋을 수 있음
- Data fetching을 Effect에서 직접 작성하는 것은 반복적이고 caching, server rendering 등 최적화하기 어려우므로 custom hook을 사용하는게 더 쉬움

#### Specifying reactive dependencies

```javascript
const serverUrl = "https://localhost:1234"; // Not a reactive value anymore
const roomId = "music"; // Not a reactive value anymore

function ChatRoom() {
  useEffect(() => {
    const connection = createConnection(serverUrl, roomId);
    connection.connect();
    return () => connection.disconnect();
  }, []); // ✅ All dependencies declared
  // ...
}
```

- Effect의 `dependencies`는 선택할 수 없음
- Effect 코드에서 참조하는 모든 reactive value들은 `dependencies`에 포함해야 함 (누락되면 lint error 발생)
- 어떤 값을 `dependencies` list에서 제거하려면 linter에게 dependency가 아님을 증명(prove)해야 함 (e.g. component 외부로 이동)
- **이 때, linter를 강제로 끄면 버그가 발생할 위험이 높아지므로 dependency가 아님을 증명하는 방법을 사용할 것**
  ```javascript
  useEffect(() => {
    // ...
    // 🔴 Avoid suppressing the linter like this:
    // eslint-ignore-next-line react-hooks/exhaustive-deps
  }, []);
  ```

#### Updating state based on previous state from an Effect

```javascript
const [count, setCount] = useState(0);

useEffect(() => {
  const intervalId = setInterval(() => {
    setCount((c) => c + 1); // ✅ Pass a state updater
  }, 1000);
  return () => clearInterval(intervalId);
}, []); // ✅ Now count is not a dependency
```

- Effect 내부에서 state variable을 직접 사용하는 대신, updater function을 통해 dependency 추가 없이 prev state로부터 next state 계산
- State variable을 직접 사용하면 불필요하게 `setup` 함수를 여러 번 실행시킬 수 있음

#### Removing unnecessary object dependencies

```javascript
useEffect(() => {
  // `options`를 component body가 아닌 Effect 내부에서 선언하면
  // `options` 때문에 `setup` 함수가 재실행 되지 않음
  const options = {
    serverUrl: serverUrl,
    roomId: roomId,
  };
  // ...
```

- `setup` 함수가 불필요하게 여러 번 호출되는 것을 막기 위해 Effect 내부에서 객체 등을 선언

#### Removing unnecessary function dependencies

```javascript
useEffect(() => {
  function createOptions() {
    return {
      serverUrl: serverUrl,
      roomId: roomId,
    };
  }
  // ...
```

- 객체와 마찬가지로 함수도 Effect 내부에서 선언해서 불필요한 re-rendering을 막을 수 있음

#### Reading the latest props and state from an Effect

```javascript
function Page({ url, shoppingCart }) {
  const onVisit = useEffectEvent((visitedUrl) => {
    logVisit(visitedUrl, shoppingCart.length);
  }); // visitedUrl, shoppingCart 값이 변경되어도 re-render를 유발하지 않음

  useEffect(() => {
    onVisit(url);
  }, [url]); // ✅ All dependencies declared
  // ...
}
```

- Reactive value에 "reacting" 하지 않고 latest value를 사용하기만 하고 싶다면, `useEffectEvent` hook을 사용해서 Effect 외부로 추출
- Effect event는 reactive 하지 않으므로 `dependencies`에 추가하지 않아도 됨

#### Displaying different content on the server and the client

- Server rendering을 사용하는 경우, component는 각 환경에서 총 두 번 실행됨
  - Server : initial HTML render
  - Client : rendering code를 한번 더 실행해서 HTML에 event handler들을 연결(attach)
- **Hydration 작업을 위해 client와 server에서 render output은 동일해야 함(identical)**
  - `localStorage`에서 값을 읽어오는 경우, server는 이 API를 사용할 수 없으므로 다른 render output이 생성될 것
  - 이런 경우, CSS로 다른 것을 보여주도록 처리
