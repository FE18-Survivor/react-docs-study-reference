# useDebugValue

> [React DevTools](https://react.dev/learn/react-developer-tools) 안에서 custom hook에 라벨을 추가하게 해주는 hook

```javascript
useDebugValue(value, format?)
```

## Reference

```javascript
import { useDebugValue } from "react";

function useOnlineStatus() {
  // ...
  useDebugValue(isOnline ? "Online" : "Offline");
  // ...
}
```

### Parameters

- `value`: React DevTools에서 나타내고 싶은 값. 모든 타입이 가능함.
- optional `format`: formatting 함수. 컴포넌트가 관찰될때 formatted된 value를 볼 수 있다. `format`이 없으면 value의 원래 형태로 볼 수 있다.

### Returns

`useDebugValue`는 return이 없다.

# useDeferredValue

> UI의 업데이트를 지연시킬 수 있는 hook이다.

```javascript
const deferredValue = useDeferredValue(value);
```

## Reference

```javascript
import { useState, useDeferredValue } from "react";

function SearchPage() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);
  // ...
}
```

### Parameters

- `value`: 지연시키고 싶은 value. 어느 타입이나 가능하다.
- optional `initialValue`: component가 초기 렌더링될때 사용되는 value 값. `initialValue`가 없으면 `value`를 대신할 수 있는 값이 없기 때문에 초기 렌더링때엔 지연되지 않는다.

### Returns

- `currentValue`: rendering에 따라 return값이 바뀐다.
  - initial render: `initialValue` or provided `value`
  - first attempt: old value
  - another re-render: updated value

### Caveats

- transition 내부에서 업데이트가 생긴다면 `useDeferredValue`는 render를 지연하지 않고, 무조건 업데이트 된 `value`를 return한다. 이미 update가 지연됐기 때문이다.
- `useDeferredValue`에 전달하는 `value`는 기본형이거나 렌더링 밖에서 생성된 객체여야 한다. 렌더링될때마다 만들어지는 객체를 전달하면 background에서 re-render가 발생해 매번 값이 바뀔것이다.
- `useDeferredValue`가 새로운 값을 받으면, 현재 렌더링 + background render 가 된다. background render는 사용자가 또 새로운 `value`를 전달하면 기존 render를 중단하고, 전달받은 값으로 다시 render한다.
- `useDeferredValue`로 인한 background re-render는 화면에 커밋되기 전까지 Effects를 실행하지 않는다.
  background re-render가 suspend되면, Effects는 데이터가 로드되고 UI가 업데이트된 이후에 실행된다.
- [etc](https://react.dev/reference/react/useDeferredValue#caveats)

## Usage

### Showing stale content while fresh content is loading

- update될 value가 보여지기 전에 그 전 value를 보여준다.

- 예를 들어 검색을 한다고 했을 때, 이전 검색결과가 새로운 결과가 나오기 전까지 나타나게 할 수 있다.

```javascript
import { useState, useDeferredValue } from "react";

function SearchPage() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);
  // ...
}
```

- 초기 렌더링을 할때엔 deferredQuery과 query(`value`로 전달되는 값)가 같다.
- 그 다음 렌더링때부터 deferredQuery는 query의 이전값을 가지고 있다가, update가 끝나면 value가 같아진다.

```javascript
//App.js
import { Suspense, useState, useDeferredValue } from 'react';
import SearchResults from './SearchResults.js';

export default function App() {
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);
  return (
    <>
      <label>
        Search albums:
        <input value={query} onChange={e => setQuery(e.target.value)} />
      </label>
      <Suspense fallback={<h2>Loading...</h2>}>
        <SearchResults query={deferredQuery} />
      </Suspense>
    </>
  );
}

//SearchResult.js
import {use} from 'react';
import { fetchData } from './data.js';

export default function SearchResults({ query }) {
  if (query === '') {
    return null;
  }
  const albums = use(fetchData(`/search?q=${query}`));
  if (albums.length === 0) {
    return <p>No matches for <i>"{query}"</i></p>;
  }
  return (
    <ul>
      {albums.map(album => (
        <li key={album.id}>
          {album.title} ({album.year})
        </li>
      ))}
    </ul>
  );
}

```

### Indicating that the content is stale

- `useDeferredValue`의 return을 통해서 렌더링중인지를 확인하고 그걸 표현할 수 있다.

```javascript
//App.js
import { Suspense, useState, useDeferredValue } from "react";
import SearchResults from "./SearchResults.js";

export default function App() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);
  const isStale = query !== deferredQuery;
  return (
    <>
      <label>
        Search albums:
        <input value={query} onChange={(e) => setQuery(e.target.value)} />
      </label>
      <Suspense fallback={<h2>Loading...</h2>}>
        <div
          style={{
            opacity: isStale ? 0.5 : 1,
            transition: isStale ? "opacity 0.2s 0.2s linear" : "opacity 0s 0s linear",
          }}
        >
          <SearchResults query={deferredQuery} />
        </div>
      </Suspense>
    </>
  );
}
```

- `isStale` value를 통해서 사용자가 입력한 값이 동일한지 확인하고 차이가 생긴다면 `opacity`를 통해 구분될 수 있게 한 코드이다.

### Deferring re-rendering for a part of the UI

- performance 최적화의 방법으로 `useDeferredValue`를 적용해 볼 수 있다.
- UI 일부가 re-render에 시간이 오래걸리고, 최적화 할 방법이 없으며 다른 UI들이 blocking되는것을 예방하고 싶을때 유용하다.
- [관련 예문](https://react.dev/reference/react/useDeferredValue#deferring-re-rendering-for-a-part-of-the-ui)

## How is deferring a value different from debouncing and throttling?

- Debouncing : 사용자가 타이핑을 멈출때까지 기다린 후에 리스트를 update 한다.
- Throttling : 일정한 간격으로 리스트를 update 한다.

둘 다 유용하지만, `useDeferredValue`가 React에 통합되어 있어서, optimizaing rendering에 더 최적화 되어있다고 소개한다.

- fixed delay가 필요없어서 user device의 환경에 따라 체감되는 속도가 달라진다.
- deferred re-render는 interruptible하기 때문에, 사용자의 신규 입력이 발생한다면 기존 re-render를 멈추고, 사용자의 입력을 처리한 후, rendering을 한다.
- rendering 중에 optimizing을 하는것이 아니라면 debouncing과 throttling도 유용할 것이다.
