# useDebugValue

## Reference

`useDebugValue(value, format?)`

`useDebugValue`는 **React DevTools**에서 커스텀 훅에 label을 추가할 수 있게 해주는 Hook

실제 코드 동작에 영향을 주지 않고 가독성, 디버깅을 위해 사용됨

- `value`: DevTools에 표시할 값
- `format`: value를 표시할 포맷팅 로직이 실행될 함수

## Usage

```jsx
import { useDebugValue } from "react";

function useOnlineStatus() {
  // ...
  useDebugValue(isOnline ? "Online" : "Offline"); // 커스텀 훅을 호출하는 컴포넌트에서 표시
  // ...
}
```

# useDeferredValue

## Reference

`const deferredValue = useDeferredValue(value, initialValue?)`

`useDeferredValue`는 값 업데이트를 즉시 반영하지 않고 지연시키는 Hook

- `value`: 지연시킬 값
- `initialValue`: 최초 렌더링 시 사용할 값

## Caveats

- `Transition` 내에서 지연되지 않음
- 원시값 또는 렌더링 외부에서 생성된 객체를 전달해서 리렌더링 피하기
- Suspense 상태로 넘어갔을 때 fallback이 아닌 지연된 값을 표시할 수 있다
- 네트워크 요청을 지연하지 않는다

## Usage

- 최초에는 전달된 값이지만, query 변경 이후 지연된 값은 하나씩 뒤쳐짐

```jsx
import { useState, useDeferredValue } from "react";

function SearchPage() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);
  // ...
}
```

- 입력 이벤트를 우선순위에 두고 SlowList 업데이트를 지연시킴

```jsx
function App() {
  const [text, setText] = useState("");
  const deferredText = useDeferredValue(text);
  return (
    <>
      <input value={text} onChange={(e) => setText(e.target.value)} />
      <SlowList text={deferredText} />
    </>
  );
}
```

> Debounce, throttling 과의 차이
>
> 지연 기법에서 디바운스, 쓰로틀링을 사용할 수 있었는데, 이들은 렌더링과는 관계없이 타이머에 따라 직접 지연할 뿐 렌더링 자체에 관여해서 지연하는 것이 아님

# useEffect

## Reference

```jsx
useEffect(setup, dependencies?)
```

### Parameters

- `setup`: Effect 로직 함수이며 옵셔널로 clean up 함수를 반환할 수 있다.
- `dependencies`: setup 함수 내에서 참조되는 모든 reactive value들이 포함된 배열. 빈 배열일 경우 컴포넌트가 리렌더링 될때마다 실행된다.

### Returns

- `useEffect의 반환 값`: `undefined`

## Usage

### 1. Connecting to an external system

- 첫 렌더: setup
- deps 변경: cleanup -> setup
- 언마운트: cleanup
- StrictMode에서는 effect가 두 번 실행

```jsx
useEffect(() => {
  // setup
  const connection = createConnection(serverUrl, roomId);
  connection.connect();
  // cleanup
  return () => {
    connection.disconnect();
  };
}, [serverUrl, roomId]);
// ...
```

### 2. Wrapping Effects in custom Hooks

- Effect 로직을 커스텀 훅으로 분리해서 재사용성을 올리기

```jsx
function useChatRoom({ serverUrl, roomId }) {
  useEffect(() => {
    const options = {
      serverUrl: serverUrl,
      roomId: roomId,
    };
    const connection = createConnection(options);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId, serverUrl]);
}

function ChatRoom({ roomId }) {
  useChatRoom({
    roomId: roomId,
    serverUrl: serverUrl,
  });
  // ...
}
```

### 3. Controlling a non-React widget

- React의 상태와 외부 상태를 맞춰줄 때 사용
- 렌더 중 순수해야 한다는 규칙 지키기위해 사용

```jsx
export default function Map({ zoomLevel }) {
  const containerRef = useRef(null);
  const mapRef = useRef(null); // React가 관리하지 않는 외부 객체를 ref에 저장

  useEffect(() => {
    if (mapRef.current === null) {
      mapRef.current = new MapWidget(containerRef.current);
    }

    const map = mapRef.current;
    map.setZoom(zoomLevel); // React State인 zoomLevel과 외부 객체 map 동기화
  }, [zoomLevel]);

  return <div style={{ width: 200, height: 200 }} ref={containerRef} />;
}
```

### 4. Fetching data with Effects

Effect에서 데이터 패칭을 할 수는 있지만 프레임워크가 있다면 프레임워크의 패칭 메커니즘을 따르는 것을 추천

- SSR에서 Effect는 실행되지 않음
- `network waterfalls`가 생성되어 느릴 수 있다. 부모 -> 자식 순으로 데이터 패칭
- caching, preload를 하지 않는다(직접 구현해야함). 컴포넌트 언마운트 -> 마운트시 다시 fetch
- `race conditions`를 고려해야 한다.

> race condition: 순서에 따라 예상과 다른 결과값이 나올 수 있는 상태.
> 비동기 작업시 실행 순서와 응답 순서가 달라져서 마지막 요청이 아닌 응답의 상태를 덮어씌우는 문제
>
> ```jsx
> useEffect(() => {
>   fetchBio(person).then(setBio); // person B를 선택했는데 A정보가 보일 수 있음
> }, [person]);
> ```
>
> 안전장치 코드를 넣어줘야한다.
>
> ```jsx
> useEffect(() => {
>   let ignore = false;
>
>   fetchBio(person).then((result) => {
>     if (!ignore) {
>       setBio(result);
>     }
>   });
>
>   return () => {
>     ignore = true;
>   };
> }, [person]);
> ```

### 5. Specifying reactive dependencies

- Effect가 참조하는 모든 `reactive value`는 deps에 포함되어야 하고 린터가 알려줌
- 린터를 끄는 것이 아닌 구조를 바꾸기

### 6. Updating state based on previous state from an Effect

- 이전 state가 Effect를 재실행하는 패턴 피하기

```jsx
useEffect(() => {
  const intervalId = setInterval(() => {
    setCount(count + 1);
  }, 1000);
  return () => clearInterval(intervalId);
}, [count]);

// 업데이터 함수 이용
useEffect(() => {
  const intervalId = setInterval(() => {
    setCount((c) => c + 1);
  }, 1000);
  return () => clearInterval(intervalId);
}, []);
```

### 7. Removing unnecessary object, function dependencies

- 렌더링 중 생성되는 객체/함수 의존성으로 사용 피하기
- 대신 Effect 내에서 생성

```jsx
useEffect(() => {
  const options = {
    serverUrl: serverUrl,
    roomId: roomId,
  };
  const connection = createConnection(options);
  connection.connect();
  return () => connection.disconnect();
}, [roomId]);
```

### 8. Reading the latest props and state from an Effect

- Effect 내부에서 최신 props와 state를 사용하고 싶지만 반응하지 않고 싶을 경우
- useEffectEvent 활용해서 의도 분리

```jsx
useEffect(() => {
  logVisit(url, shoppingCart.length);
}, [url, shoppingCart]);

function Page({ url, shoppingCart }) {
  const onVisit = useEffectEvent((visitedUrl) => {
    logVisit(visitedUrl, shoppingCart.length);
  });

  useEffect(() => {
    onVisit(url);
  }, [url]); // url에만 반응하지만 url, shoppingCart 모두 읽기 가능
}
```

### 9. Displaying different content on the server and the client

- 서버와 클라이언트에서 첫 렌더의 결과는 같아야 함
- 서버와 클라이언트의 첫 렌더를 동일하게 한 후 클라이언트에서 다른 UI 보여주는 패턴

```jsx
function MyComponent() {
  const [didMount, setDidMount] = useState(false);

  useEffect(() => {
    setDidMount(true);
  }, []);

  if (didMount) {
    //
  } else {
    //
  }
}
```
