## [useEffectEvent](https://react.dev/reference/react/useEffectEvent)

- Effect에서 non-reactive logic을 분리해서 reusable function(Effect Event)으로 만들어 주는 hook

### Reference

- `useEffectEvent(callback)`
- Parameters
  - `callback` : Effect event logic. 항상 reactive values의 latest value에 접근하게 됨
- Returns
  - Effect event function
  - `useEffect`, `useLayoutEffect`, `useInsertionEffect` 등 Effect 내부에서 사용 가능
- Caveats
  - Effect event function은 반드시 Effect 내부에서만 호출해야 함 (다른 component나 hook의 ㅔrop으로 전달하지 못하게 linter가 강제함)
  - Effect event를 Effect의 `dependencies` array를 우회하는 용도로 사용하지 말 것
  - Non-reactive logic을 위해서만 사용할 것 (changing values에 의존하지 않기 위한 목적으로 사용하지)

### Usage

#### Reading the latest props and state

```javascript
function Page({ url }) {
  const { items } = useContext(ShoppingCartContext);
  const numberOfItems = items.length;

  const onNavigate = useEffectEvent((visitedUrl) => {
    // `numberOfItems`의 latest value에 접근하면서, 이 값이 변경되어도 Effect를 다시 실행시키지 않음
    logVisit(visitedUrl, numberOfItems);
  });

  useEffect(() => {
    onNavigate(url);
    // `url`이 변경될 때마다 navigate를 다시 실행해야 하므로
    // `url`은 dependencies array에 포함
  }, [url]);
}
```

- Effect 내부에서 reactive value에 접근하려면 `dependencies` array에 추가해서, reactive value가 변경될 때마다 Effect를 다시 실행시켜야 함
- Effect를 다시 실행시키지 않으면서 props 또는 state의 가장 최신 값(latest value)만 사용하고 싶을 수 있음
- 이렇게 non-reactive values를 사용하는 logic을 Effect Event에 포함

## [useId](https://react.dev/reference/react/useId)

- Unique ID를 생성해 주는 hook

### Reference

- `useId()`
- Parameters : none
- Returns : hook을 호출한 component 마다 생성된 unique ID string
- Caveats
  - `use()`에 사용할 cache keys를 생성할 때 사용하면 안 된다.
    - ID는 component가 rendering 되는 동안 변경될 수 있음
    - **`use()`에 사용할 cache keys는 data로부터 생성되어야 함**
  - List에 사용할 key를 생성할 때 사용하면 안 된다.
    - **List의 key는 data로부터 생성되어야 함**
  - `useId()`는 async server components 에서 사용할 수 없음

### Usage

#### Generating unique IDs for accessibility attributes

```javascript
function PasswordField() {
  const passwordHintId = useId();

  //...

  return (
    <>
      <input type="password" aria-describedby={passwordHintId} />
      <p id={passwordHintId}>{/*...*/}</p>
    </>
  );
}
```

- `aria-describedby` 등 HTML accessibility attributes는 서로 다른 두 tag가 연관되어 있다는 것을 나타냄
- 위 예제에서는, `input` element가 `p`에 의해 설명된다(described)는 것을 나타냄
- 이 ID를 하드코딩 하면, React에서 component가 여러 번 rendering 되는 경우 ID가 중복될 가능성이 있음
- `useId()`를 사용하면 특정 component에 대해 항상 고유한 ID를 생성
  ```javascript
  export default function App() {
    return (
      <>
        <h2>Choose password</h2>
        <PasswordField />
        <h2>Confirm password</h2>
        <PasswordField />
      </>
    );
  }
  ```
- Server rendering 환경에서 `useId()`를 사용하려면 client와 server에서 component tree가 동일해야 함(identical)
  - Server에서 render한 tree가 client와 다르면 생성된 ID가 match 되지 않음
- `useId()`가 counter를 증가시키는 방법보다 좋은 이유 (e.g. `nextId++`)
  - React에서 server rendering을 하면 server에서 render한 HTML을 client에서 hydration 할 때 HTML이 동일해야 함
  - Incrementing counter는 server와 client 간에 HTML이 달라지게 만들 수 있음
  - **`useId()`를 사용하면 server와 client의 render output이 일치하고 hydration이 동작하는 것을 보장할 수 있음**
  - React에서 `useId`는 component를 호출한 parent path를 통해 생성되기 때문에, client와 server tree가 동일함

#### Generating IDs for several related elements

```javascript
export default function Form() {
  const id = useId();
  return (
    <form>
      <label htmlFor={id + "-firstName"}>First Name:</label>
      <input id={id + "-firstName"} type="text" />
      <hr />
      <label htmlFor={id + "-lastName"}>Last Name:</label>
      <input id={id + "-lastName"} type="text" />
    </form>
  );
}
```

- `useId()`를 여러 연관된 element들에 shared prefix로 사용할 수 있음
- ID 하나를 만들어서 여러 element에 사용할 수 있는 방법

#### Specifying a shared prefix for all generated IDs

- Single page에 여러 개의 독립적인 React app을 render하는 경우, `createRoot` 또는 `hydrateRoot` 호출 시 `identifierPrefix` option을 사용해서 각 app에 대해 고유한 prefix를 지정할 수 있음

  ```javascript
  const root1 = createRoot(document.getElementById("root1"), {
    identifierPrefix: "my-first-app-",
  });
  root1.render(<App />);

  const root2 = createRoot(document.getElementById("root2"), {
    identifierPrefix: "my-second-app-",
  });
  root2.render(<App />);
  ```

- `useId()` hook은 `identifierPrefix`에 지정한 값을 prefix로 사용해서 ID를 생성

  ```javascript
  function PasswordField() {
    const passwordHintId = useId();
    console.log(passwordHintId);
    // App A : "my-first-app-r_0_"
    // App B : "my-second-app-r_1_"

    return (
      <>
        <label>
          Password:
          <input type="password" aria-describedby={passwordHintId} />
        </label>
        <p id={passwordHintId}>
          The password should contain at least 18 characters
        </p>
      </>
    );
  }
  ```

#### Using the same ID prefix on the client and the server

```javascript
// Server
import { renderToPipeableStream } from "react-dom/server";
const { pipe } = renderToPipeableStream(<App />, {
  identifierPrefix: "react-app1",
});

// Client
import { hydrateRoot } from "react-dom/client";
const domNode = document.getElementById("root");
const root = hydrateRoot(domNode, reactNode, {
  identifierPrefix: "react-app1",
});
```

- Single page에 둘 이상의 React app을 render 하고, React app 중 server-rendered 되는 app이 있는 경우,
- **client에서 `hydrateRoot`에 `identifierPrefix`로 전달한 값과 server API의 `identifierPrefix`로 전달한 값이 같아야 함** (e.g. `renderToPipeableStream`)

## [useLayoutEffect](https://react.dev/reference/react/useLayoutEffect)

- Browser가 screen을 repaint 하기 이전에 Effect를 실행시켜 주는 hook
- Browser repaint 이전에 layout measurements를 수행할 때 사용
- `useEffect`와 동일하지만 실행 시점이 다르다.
  1. `useLayoutEffect`의 Effect 실행
  2. Browser painting
  3. Browser가 화면을 그린 뒤 `useEffect`의 Effect 실행
- **성능에 영향을 줄 수 있으므로, 가능하면 `useEffect`를 먼저 사용한다.**

### Reference

- `useLayoutEffect(setup, dependencies?)`
- Parameters
  - `setup` : 실행할 Effect logic
  - `dependencies?` : `setup` 내부에서 사용된 reactive values
- Returns : `undefined`
- Caveats
  - `setup` 함수 내부에서 실행되는 모든 코드 및 state update는 **browser에서 screen을 repainting 하는 것을 block** 하므로, 과도하게 사용하면 app이 멈출 수 있다.
  - `setup` 함수 내부에서 state update를 trigger 하면 React는 **`useEffect`를 포함한 모든 Effect들을 즉시 실행**한 후 re-rendering을 진행한다.
    - Browser가 화면을 그리기 전에 모든 Effect들을 정리하고 새로운 rendering cycle을 시작하기 위해 대기중인 Effect들을 처리하는 것

### Usage

#### Measuring layout before the browser repaints the screen

```javascript
function Tooltip() {
  const ref = useRef(null);
  const [tooltipHeight, setTooltipHeight] = useState(0); // You don't know real height yet

  useLayoutEffect(() => {
    const { height } = ref.current.getBoundingClientRect();
    setTooltipHeight(height); // Re-render now that you know the real height
  }, []);

  // ...use tooltipHeight in the rendering logic below...
}
```

- 대부분의 component들은 JSX를 반환하기만 하고, browser가 layout을 계산해서 repaint 해 준다.
- Component가 render 되기 전에 size 등을 사용해서 layout을 계산해야 할 때 `useLayoutEffect` 활용 가능 (e.g. Tooltip 등)
- 동작 순서
  1. `Tooltip`은 처음에 `tooltipHeight`이 0인 상태로 render 됨
  2. React는 `Tooltip`을 DOM에 배치한 뒤 `useLayoutEffect` 코드 실행
  3. `useLayoutEffect` 에서는 `Tooltip`의 height을 계산해서 state를 변경하고 re-render를 trigger
  4. `Tooltip`은 변경된 `tooltipHeight` 값을 사용해서 정확한 layout으로 render
  5. React는 DOM을 갱신하고, browser는 tooltip을 표시
- 이 때, `tooltipHeight` 초깃값은 0 이지만 `useLayoutEffect` 내부에서 정확히 계산된 height으로 변경했기 때문에 height이 0인 상태의 `Tooltip`은 그려지지 않아서 화면에 보이지 않음
