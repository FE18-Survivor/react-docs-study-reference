# <a href="https://react.dev/reference/react/useEffectEvent">useEffectEvent</a>

- useEffectEvent는 Effect 안에서 값이 바뀌어도 이펙트를 다시 실행시킬 필요는 없는 코드만 분리해주는 React hook이다.

## Reference

`useEffectEvent(callback)`

**Parameters**
  - `callback` : Effect Event로 분리하고싶은 로직을 담은 함수이다. 이 함수는 언제나 최신의 `props` 와 `state`를 읽어올 수 있다.

**Returns**
  - `Effect Event function` : `useEffect` 나 `useLayoutEffect` 내부에서 호출할 수 있는 함수를 반환한다. 

>[!WARNING]
> - Effect 내부에서만 호출 해야한다.
> - 의존성을 피하기 위한 편법이 아니다.
> - 값이 바뀐다고 해서 이펙트가 재실행될 필요가 전혀 없는 경우에만 사용한다.

## Usage

```javascript
function Page({ url }) {
  const { items } = useContext(ShoppingCartContext);
  const numberOfItems = items.length;

  // 1. 이펙트 이벤트 정의 : 비반응성 로직 추출
  // numberOfItems가 아무리 변해도 이 함수 때문에 이펙트가 재실행되진 않음
  const onNavigate = useEffectEvent((visitedUrl) => {
    logVisit(visitedUrl, numberOfItems); // 하지만 실행될 땐 항상 최신 개수를 읽음
  });

  // 2. 이펙트 설정: 반응성 로직
  useEffect(() => {
    onNavigate(url); 
  }, [url]); // 오직 url이 바뀔 때만 이펙트가 실행됨
}
```

# <a href="https://react.dev/reference/react/useId">useId</a>

- `useId`는 접근성 속성에 전달하기 위한 고유한 ID를 생성하는 React Hook이다.
- 단순히 중복되지 않는 값을 만드는 것을 넘어, SSR 환경에서도 서버와 클라이언트의 ID를 일치시켜 Hydration 에러를 방지하는 것이 핵심이다.

## Reference

`useId()`

**Parameters**

- ❌

**Returns**

- 해당 컴포넌트의 특정 호출과 연관된 고유한 ID 문자열을 반환한다.

>[!WARNING]
> - **최상위 레벨**에서만 **호출** 가능하다. (반복문, 조건문 내 호출 금지)
> - 리스트의 key는 반드시 데이터에서 가져온 **고유 값**을 사용해야 한다.
> - 현재 **비동기**로 작성된 서버 컴포넌트 내에서는 **사용할 수 없다.**
> - ID는 컴포넌트 마운트 시에는 안정적이지만 렌더링 중에 변할 가능성이 있으므로, **캐싱을 위한 키**로 **적합하지 않다.**

## Usage

### **Generating unique IDs for accessibility attributes**

```javascript
function PasswordField() {
  const passwordHintId = useId(); // 매번 고유한 ID 생성
  return (
    <>
      <label>
        Password:
        <input type="password" aria-describedby={passwordHintId} />
      </label>
      <p id={passwordHintId}>비밀번호는 18자 이상이어야 합니다.</p>
    </>
  );
}
```

- 일반 HTML처럼 `id="password-hint"`라고 직접 적으면, 같은 컴포넌트를 한 페이지에 두 번 썼을 때 ID 중복이 발생한다. useId는 이를 자동으로 해결해준다.

### **Generating IDs for several related elements**

```javascript
function Form() {
  const id = useId();
  return (
    <form>
      <label htmlFor={id + '-firstName'}>First Name:</label>
      <input id={id + '-firstName'} type="text" />
      <hr />
      <label htmlFor={id + '-lastName'}>Last Name:</label>
      <input id={id + '-lastName'} type="text" />
    </form>
  );
}
```

- 요소마다 useId를 호출할 필요 없이, **하나의 ID**를 생성해 **접미사**를 붙여 사용하면 편리하다.

### **Specifying a shared prefix for all generated IDs**

```javascript
// 앱 1에는 'app1-' 접두사 부여
const root1 = createRoot(document.getElementById('root1'), {
  identifierPrefix: 'app1-'
});

// 앱 2에는 'app2-' 접두사 부여
const root2 = createRoot(document.getElementById('root2'), {
  identifierPrefix: 'app2-'
});
```

- 한 페이지에 독립적인 리액트 앱이 여러 개 있다면, createRoot 설정에서 접두사를 붙여 ID 충돌을 완전히 차단할 수 있다.

### **Using the same ID prefix on the client and the server**

```javascript
// [Server] renderToPipeableStream 등 서버 API 사용 시
import { renderToPipeableStream } from 'react-dom/server';

const { pipe } = renderToPipeableStream(
  <App />,
  { identifierPrefix: 'react-app1' } // 1. 서버에서 접두사 설정
);

// [Client] hydrateRoot 호출 시
import { hydrateRoot } from 'react-dom/client';

const domNode = document.getElementById('root');
const root = hydrateRoot(
  domNode,
  <App />,
  { identifierPrefix: 'react-app1' } // 2. 클라이언트에서도 반드시 동일한 값 전달
);
```

- 한 페이지에 여러 개의 독립적인 React 앱이 있고 그중 일부가 서버에서 렌더링된다면, 서버와 클라이언트 양쪽 설정에서 동일한 접두사를 넘겨주어야 한다.

- `useId`는 서버와 클라이언트의 컴포넌트 트리가 똑같을 때만 동일한 ID를 생성한다. 접두사가 다르면 서버가 만든 HTML의 ID와 클라이언트가 만든 ID가 충돌하여 Hydration 에러가 발생한다.

- 페이지에 React 앱이 하나만 있다면 이 설정을 생략해도된다.

<br />

>[!NOTE] 왜 카운터 변수(i++)보다 좋은가요?
> - **`증분 카운터의 문제`** : 서버는 여러 요청을 동시에 처리하므로 카운터가 꼬일 수 있고, 클라이언트와 서버의 렌더링 순서가 조금만 달라도 ID가 일치하지 않게 된다.
> - **`useId의 해결책`** : 리액트는 컴포넌트의 **트리 경로**를 기반으로 ID를 생성하기 때문에, 렌더링 순서와 상관없이 서버와 클라이언트에서 항상 같은 ID를 만들어낸다.

# <a href="https://react.dev/reference/react/useLayoutEffect#">useLayoutEffect</a>

- **useLayoutEffect**는 브라우저가 화면을 그리기(Repaint) 직전에 **동기적으로 실행되는 Hook**이다.

- useEffect와 사용법은 같지만, 화면에 변화가 반영되기 전에 **DOM을 측정**하거나 **UI를 수정**해야 할 때 사용한다.

<br />

## **Reference**

**`useLayoutEffect(setup, dependencies?)`**

### **Parameters**

- **setup** : Effect의 로직을 담은 함수이다. 브라우저가 화면을 그리기 전에 실행되며, cleanup 함수를 반환할 수 있다.

- **dependencies (optional)** : setup 코드 내에서 참조된 모든 반응형 값(props, state 등)의 목록이다.

### *8Returns**

- **undefined**를 반환한다.

> [!WARNING]
> - **성능 저하 주의** : 내부 로직과 상태 업데이트가 완료될 때까지 **브라우저의 화면 그리기가 차단(Blocking)** 된다.
> 
> - **우선순위** : 대부분의 경우 성능을 위해 useEffect를 사용하고, 화면 깜빡임이 발생하는 경우에만 useLayoutEffect로 교체한다.
> 
> - **SSR 주의** : 서버 사이드 렌더링에서는 작동하지 않으며 클라이언트에서만 실행된다.

<br />

## **Usage**

### **Measuring layout before the browser repaints the screen**

- 사용자가 레이아웃의 변화를 눈치채지 못하게, 화면을 그리기 전 **빠르게 수정**을 완료하는 것이 핵심이다.

```javascript
function Tooltip({ targetRect, children }) {
  const ref = useRef(null);
  const [tooltipHeight, setTooltipHeight] = useState(0);

  // 1. 브라우저가 페인팅하기 직전에 동기적으로 실행
  useLayoutEffect(() => {
    const { height } = ref.current.getBoundingClientRect();
    setTooltipHeight(height); // 2. 즉시 재렌더링을 발생시켜 위치를 보정함
  }, []);

  // 3. 사용자는 보정이 끝난 최종 상태의 화면만 보게 됨 (깜빡임 없음)
  let tooltipY = targetRect.top - tooltipHeight;
  if (tooltipY < 0) tooltipY = targetRect.bottom;

  return (
    <div ref={ref} style={{ position: 'absolute', top: `${tooltipY}px` }}>
      {children}
    </div>
  );
}
```

## **Troubleshooting**

### **useLayoutEffect does nothing on the server error**

- 이 Hook은 실제 브라우저 레이아웃 정보가 필요할 때 사용하므로, 서버 환경에서는 무의미하다.
  
  - 단순히 데이터를 가져오는 로직이라면 useEffect로 변경한다.
  
  - isMounted 상태(boolean)를 활용해 마운트 이후에만 렌더링되도록 처리한다.
  
  - 서버 렌더링 지원이 필요하다면 useSyncExternalStore 사용을 검토한다.

<br />

>[!NOTE] useEffect vs useLayoutEffect 한 줄 비교
> - `useEffect` : "일단 화면을 보여주고 나서 일을 처리하자" (권장)
> - `useLayoutEffect` : "사용자가 보기 전에 일을 완벽하게 끝내놓자" (특수 케이스)
