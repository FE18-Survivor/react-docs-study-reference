# useEffectEvent

> `useEffectEvent`는 Effect에서 non-reactive 로직을 추출하여 Effect Event 라는 reusable 함수로 만들게 해준다.

## Reference

`useEffect`같은 Effect 안에서 호출할 수 있다.

```javascript
import { useEffectEvent, useEffect } from "react";

function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showNotification("Connected!", theme);
  });

  useEffect(() => {
    const connection = createConnection(serverUrl, roomId);
    connection.on("connected", () => {
      onConnected();
    });
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]);

  // ...
}
```

### Prarmeters

- `callback`: Effect Event 로직을 갖고 있는 함수. `callback`이 호출되면 항상 가장 최근의 `props`와 `state`에 접근한다.

### Returns

- `Effect Event function`: return 되는 함수를 `useEffect`, `useLayoutEffect`, `useInsertionEffect` 내부에서 호출 할 수 있다.

### Caveats

- Only call inside Effects: 다른 컴포넌트나 훅이 아니라, Effect 내부에서만 호출해야한다. [`eslint-plugin-react-hooks`](https://react.dev/reference/eslint-plugin-react-hooks)에서 규칙을 정할 수 있다.
- Not a dependency shortcut: dependencies에서 빼기 위해 사용한다면 버그를 찾기 어려워진다.
- Use for non-reactive logic: `value`의 변화에 의존하지 않는 로직에만 사용해야한다.

## Usage

### [Reading the latest props and state](https://react.dev/reference/react/useEffectEvent#reading-the-latest-props-and-state)

`useEffect`같은 Effect속에 value가 있다면 dependency array에 당연히 포함되기 때문에, value가 바뀔때마다 Effect 또한 re-run 하게 된다.

Effect 내부에서 가장 최신값의 props나 state를 활용하고 싶은데, effect를 re-run 하고싶지 않을때 `useEffectEvent`를 활용할 수 있다.

```javascript
import { useEffect, useContext, useEffectEvent } from "react";

function Page({ url }) {
  const { items } = useContext(ShoppingCartContext);
  const numberOfItems = items.length;

  const onNavigate = useEffectEvent((visitedUrl) => {
    logVisit(visitedUrl, numberOfItems);
  });

  useEffect(() => {
    onNavigate(url);
  }, [url]);

  // ...
}
```

예시 코드를 보면, `url`이 바뀌면 Effect는 re-run하지만, numberOfItems가 바뀔땐 Effect가 다시 실행되지 않은 채 최신 값을 알 수 있게 된다.

# useId

> `useId`는 accessibility attributes(접근성 속성)에 전달할 수 있는 unique key를 생성하는 hook 이다.

## Reference

```javascript
import { useId } from 'react';

function PasswordField() {
  const passwordHintId = useId();
  // ...
```

- Parameters: 없음
- Returns: 고유 ID 문자열

### Caveats

- `useId`는 Hook 이기 때문에 컴포넌트의 상단에서만 호출 할 수 있다.
- `useId`로 만든 Id는 `use()`의 cache key로 사용되면 안된다. Id는 컴포넌트가 마운트 될땐 안정적이지만 렌더링중에는 값이 바뀔수 있기 때문에, cache key는 data로 해야한다.
- 만들어진 Id가 list의 key로 사용될 수 없다.
- async Server Components에서 사용할 수 없다.

## Usage

unique key를 생성하여 accessibility attributes에 추가하거나, html태그의 id로 활용할 수 있다. 또한 id와 다른 값을 조합하여 연관된 요소들을 관리하고, id 자체를 prefix로 사용할 수 있다.

**[Generating unique IDs for accessibility attributes](https://react.dev/reference/react/useId#generating-unique-ids-for-accessibility-attributes)**

```javascript
import { useId } from 'react';

function PasswordField() {
  const passwordHintId = useId();
  // ...
```

```html
<>
<input type="password" aria-describedby="{passwordHintId}" />
<p id="{passwordHintId}"></p>
```

**[Generating IDs for several related elements](https://react.dev/reference/react/useId#generating-ids-for-several-related-elements)**

```javascript
import { useId } from "react";

export default function Form() {
  const id = useId();
  return (
    <form>
      <label htmlFor={id + "-firstName"}>First Name:</label>
      <input id={id + "-firstName"} type="text" />
      <hr />
      <label htmlFor={id + "-lastName"}>Last Name:</label>
      <input id={id + "-lastName"} type="text" />
    </form>
  );
}
```

**[Specifying a shared prefix for all generated IDs](https://react.dev/reference/react/useId#specifying-a-shared-prefix-for-all-generated-ids)**

**[Using the same ID prefix on the client and the server](https://react.dev/reference/react/useId#using-the-same-id-prefix-on-the-client-and-the-server)**

# useLayoutEffect

> useLayoutEffect는 browser가 화면을 repaint 하기 전에 동작하는 useEffect의 한 종류이다.

## Reference

```javascript
import { useState, useRef, useLayoutEffect } from 'react';

function Tooltip() {
  const ref = useRef(null);
  const [tooltipHeight, setTooltipHeight] = useState(0);

  useLayoutEffect(() => {
    const { height } = ref.current.getBoundingClientRect();
    setTooltipHeight(height);
  }, []);
  // ...
```

### Parameters

- `setup` : Effect의 로직이 있는 함수. cleanup 함수 또한 포함될 수 있다. components가 commit 되기 전에 `setup` 함수가 먼저 실행된다. 모든 commit이 끝나면, 전달받은 cleanup 함수가 제일먼저 실행되고, 그 후에 new value로 `setup`이 실행된다.
- optional `dependencies` : `setup`이 참조하는 모든 reactive values의 list.

- Returns : `undefined`

### Caveats

- Strict mode 에선, development 환경에서만 `setup` + `cleanup` cycle이 한번 더 동작한다. 이는 cleanup 함수와 setup이 "mirror"처럼 되어있는지, cleanup이 setup의 기능을 멈추거나 되돌릴 수 있는지 확실하게 하기 위해서이다. 여기서 문제가 발생한다면, cleanup함수를 구현하는것이 좋다.
- dependencies에 function이나 object가 있으면 extra re-run을 발생시킬 수 있는 위험이 있다. 불필요한 object나 function은 제거하는것이 좋다.
- Effect는 client에서만 동작한다.
- `useLayoutEffect`에 있는 코드와 그로인한 state의 update는 browser의 repaint를 block하여 화면이 느려질 수도 있다. 가능하다면 `useEffect`를 권장한다.
- `useLayoutEffect`에서 state update가 trigger되면, React는 `useEffect`를 포함한 모든 Effect를 즉시 실행한다.

## Usage

### Measuring layout before the browser repaints the screen

대부분의 component들은 position이나 size를 신경쓰지 않고 JSX코드만 return한다. 그리고 browser가 layout을 계산하고 repaint 한다.

하지만 tooltip처럼 위치나 폭이 고정되어야 하는 component가 있다면 `useLayoutEffect`를 사용해볼 수 있다.

```javascript
function Tooltip() {
  const ref = useRef(null);
  const [tooltipHeight, setTooltipHeight] = useState(0); // You don't know real height yet

  useLayoutEffect(() => {
    const { height } = ref.current.getBoundingClientRect();
    setTooltipHeight(height); // Re-render now that you know the real height
  }, []);

  // ...use tooltipHeight in the rendering logic below...
}
```

**렌더링 과정**

1. Tooltip이 초기 `tooltipHeight = 0` 상태로 렌더링된다.

2. React는 이를 DOM에 배치하고 useLayoutEffect 안의 코드를 실행한다.

3. useLayoutEffect는 tooltip 콘텐츠의 높이를 측정하고, 즉시 다시 렌더링을 trigger 한다.

4. Tooltip이 실제 tooltipHeight 값을 가지고 다시 렌더링된다.

5. React는 이를 DOM에 업데이트하고, browser가 마침내 tooltip을 화면에 표시한다.

### TroubleShooting

`useLayoutEffect`는 server에서 동작하지 않는다. 레이아웃 정보가 없기 때문이다. 따라서 다음과 같은 해결방법을 적용해 볼 수 있다.

- `useEffect`사용하기
- component에 `client-only`표시하기
- hydration 이후에 `useLayoutEffect`를 사용하는 컴포넌트 렌더링 하기
- `useSyncExternalStore` 사용 고려하기
