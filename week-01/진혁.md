# useActionState

useActionState는 form action의 결과를 기반으로 상태를 업데이트 해주는 Hook

## Reference

`useActionState(action, initialState, permalink?)`

- useActionState를 컴포넌트 최상위 레벨에서 호출시, form action 이 호출될 때 업데이트 되는 컴포넌트 상태를 만들 수 있음
- useActionState에는 기존 form action 함수와 초기 state를 전달
- form state는 폼이 마지막으로 제출됐을때 action이 반환한 값
- 서버 함수와 사용하면 hydration이 완료되기 전에 form을 제출한 결과를 보여줄수 있음
- return : form에서 사용할 새로운 action, 최신 form state , 처리중인지 여부

```javascript
async function increment(previousState, formData) {
  return previousState + 1;
}

function StatefulForm({}) {
  const [state, formAction] = useActionState(increment, 0);
  return (
    <form>
      {state}
      <button formAction={formAction}>Increment</button>
    </form>
  );
}
```

## Parameters

- fn
  - 폼이 제출되거나 버튼을 눌렀을때 호출하는 함수
  - 함수가 호출되면 첫번째 인자로는 form의 이전 state, 다음 인자들은 form action 값들을 받음
- initialState
  - state의 초기값
- optional permalink
  - form이 수정하는 고유한 URL
  - 동적 컨텐츠가 있는 페이지에서 사용
  - fn이 서버함수고 javasScript 번들이 로드되기 전에 폼이 제출되면, 브라우저가 지정된 permalink URL로 이동
  - React가 state를 전달할 수 있도록 목적지 페이지에서 동일한 form 컴포넌트가 렌더링 되어야함

## Returns

- current state
  - 첫 렌더링시 initialSate
  - action 호출 이후에는 action이 반환한 값
- form 의 action prop이나 button의 formAction prop 으로 전달할 수 있는 새 action
- isPending 플래그

## Caveats

- React Server Components를 지원하는 프레임워크에서 사용하면 클라이언트에서 자바스크립트가 실행되기 전에도 form을 interactive하게 만들 수 있음
- Server Component 없이 사용하면 컴포넌트 local state랑 같음
- useActionState에 전달한 함수는 첫 번째 인자로 이전/초기 state를 추가로 받음
- useActionState 없이 form action으로 직접 사용할때와 함수 시그니쳐가 다름

## Usage

```javascript
import { useActionState } from 'react';
import { action } from './actions.js';

function MyComponent() {
  const [state, formAction] = useActionState(action, null);
  // ...
  return <form action={formAction}>{/* ... */}</form>;
}
```

- useActionState가 반환하는 항목들
  - current state : 초기에는 initial state, 이후에는 action의 반환값
  - new action: form의 action prop으로 전달하거나 startTranslation 안에서 호출할 action
  - pending state
- form이 제출되면 전달한 함수가 호출되고 반환값이 current state가 됨
- 전달한 action은 추가적인 첫번째 인자로 current state를 받음

## Troubleshooting

- useActionState를 사용하면 form action이 추가적인 인자를 받아 인자 순서가 `(currentState, formData)`로 변경됨



# useCallback
useCallback 은 같은 함수를 다시 만들지 않게 memoization 해주는 react hook
```javascript
import { useCallback } from 'react';

export default function ProductPage({ productId, referrer, theme }) {
  const handleSubmit = useCallback((orderDetails) => {
    post('/product/' + productId + '/buy', {
      referrer,
      orderDetails,
    });
  }, [productId, referrer]);
}
```
## Parameters
### useCallback(fn, dependencies)
- fn
  - 캐시하고 싶은 함수
- dependencies
  - 함수가 의존하고 있는 값들의 리스트
  - props, state, 컴포넌트에서 선언된 모든 변수와 함수

## Returns
- 렌더링시 의존성 값 변경 X -> 이전에 저장된 동일한 함수를 반환
- 의존성 값 변경 O -> 현재 렌더에서 전달한 함수를 반환하고 저장

## Caveats
- 최상위 컴포넌트 레벨이나 커스텀 Hook 내부에서만 호출 가능
- 루프나 조건문 안에서는 호출 불가
- 특정한 이유가 없으면 react가 캐시된 함수를 버리지 않음

## Usage
```javascript
import { useCallback } from 'react';

function ProductPage({ productId, referrer, theme }) {
  const handleSubmit = useCallback((orderDetails) => {
    post('/product/' + productId + '/buy', {
      referrer,
      orderDetails,
    });
  }, [productId, referrer]);
  // ...
}
```
- useCallback 첫번째 인자로 캐시하고 싶은 함수, 두번째 인자로는 의존성 리스트
- 초기 렌더링 시 전달한 함수를 그대로 반환
- 이후 의존성 리스트가 바뀌면 새로 렌더링시 전달한 함수를 반환
## Example
```javascript
function ProductPage({ productId, referrer, theme }) {
  return (
    <div className={theme}>
      <ShippingForm onSubmit={handleSubmit} />
    </div>
  );
}
```
- 부모 리렌더링으로 자식 성능 문제
- theme 변경으로 ShippingFrom 리렌더링
### 1차 최적화
```javascript
import { memo } from 'react';

const ShippingForm = memo(function ShippingForm({ onSubmit }) {
  // ...
});
```
- memo 를 사용해서 props가 같으면 리렌더링 X
```javascript
function ProductPage({ productId, referrer, theme }) {
  function handleSubmit(orderDetails) {
    post('/product/' + productId + '/buy', {
      referrer,
      orderDetails,
    });
  }

  return (
    <div className={theme}>
      <ShippingForm onSubmit={handleSubmit} />
    </div>
  );
}

```
- JavaScript에서 함수는 렌더링마다 새로운 객체
- memo가 동작하지 않고 리렌더링
```javascript
const handleSubmit = useCallback((orderDetails) => {
    post('/product/' + productId + '/buy', {
      referrer,
      orderDetails,
    });
  }, [productId, referrer]);
```
- useCallback으로 함수 유지
- memo 최적화가 동작

## Memoized 된 함수에서 상태 업데이트
### todos를 기반으로 다음 상태 계산
```javascript
function TodoList() {
  const [todos, setTodos] = useState([]);

  const handleAddTodo = useCallback((text) => {
    const newTodo = { id: nextId++, text };
    setTodos([...todos, newTodo]);
  }, [todos]);
}
```
### 업데이터 함수를 사용해서 의존성 제거 가능
```javascript
function TodoList() {
  const [todos, setTodos] = useState([]);

  const handleAddTodo = useCallback((text) => {
    const newTodo = { id: nextId++, text };
    setTodos(todos => [...todos, newTodo]);
  }, []); // ✅ todos 의존성 제거
}
```
## Effect가 너무 자주 실행되는 문제
### Effect 안에서 함수를 호출하는 경우
```javascript
function ChatRoom({ roomId }) {
  function createOptions() {
    return {
      serverUrl: 'https://localhost:1234',
      roomId: roomId
    };
  }

  useEffect(() => {
    const options = createOptions();
    const connection = createConnection(options);
    connection.connect();
  }, [createOptions]); // 🔴 매 렌더마다 변경됨
}
```
### 해결방법
- useCallback 사용
- 함수를 Effect 내부로 이동

## 커스텀 Hook 최적화
- 커스텀 Hook 안에서 반환하는 함수는 useCallback을 사용하는것을 권장

## Troubleshooting
- useCallback이 매번 다른 함수를 반환할 때
  - 의존성 배열 확인
- 리스트 루프에서 useCallback을 써야할 때
  - 아이템 컴포넌트를 분리
  - useCallback 대신 컴포넌트 자체에 memo 사용
