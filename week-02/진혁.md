# useCallback

useCallback 은 같은 함수를 다시 만들지 않게 memoization 해주는 react hook

```javascript
import { useCallback } from 'react';

export default function ProductPage({ productId, referrer, theme }) {
  const handleSubmit = useCallback(
    (orderDetails) => {
      post('/product/' + productId + '/buy', {
        referrer,
        orderDetails,
      });
    },
    [productId, referrer]
  );
}
```

## Parameters

### useCallback(fn, dependencies)

- fn
  - 캐시하고 싶은 함수
- dependencies
  - 함수가 의존하고 있는 값들의 리스트
  - props, state, 컴포넌트에서 선언된 모든 변수와 함수

## Returns

- 렌더링시 의존성 값 변경 X -> 이전에 저장된 동일한 함수를 반환
- 의존성 값 변경 O -> 현재 렌더에서 전달한 함수를 반환하고 저장

## Caveats

- 최상위 컴포넌트 레벨이나 커스텀 Hook 내부에서만 호출 가능
- 루프나 조건문 안에서는 호출 불가
- 특정한 이유가 없으면 react가 캐시된 함수를 버리지 않음

## Usage

```javascript
import { useCallback } from 'react';

function ProductPage({ productId, referrer, theme }) {
  const handleSubmit = useCallback(
    (orderDetails) => {
      post('/product/' + productId + '/buy', {
        referrer,
        orderDetails,
      });
    },
    [productId, referrer]
  );
  // ...
}
```

- useCallback 첫번째 인자로 캐시하고 싶은 함수, 두번째 인자로는 의존성 리스트
- 초기 렌더링 시 전달한 함수를 그대로 반환
- 이후 의존성 리스트가 바뀌면 새로 렌더링시 전달한 함수를 반환

## Example

```javascript
function ProductPage({ productId, referrer, theme }) {
  return (
    <div className={theme}>
      <ShippingForm onSubmit={handleSubmit} />
    </div>
  );
}
```

- 부모 리렌더링으로 자식 성능 문제
- theme 변경으로 ShippingFrom 리렌더링

### 1차 최적화

```javascript
import { memo } from 'react';

const ShippingForm = memo(function ShippingForm({ onSubmit }) {
  // ...
});
```

- memo 를 사용해서 props가 같으면 리렌더링 X

```javascript
function ProductPage({ productId, referrer, theme }) {
  function handleSubmit(orderDetails) {
    post('/product/' + productId + '/buy', {
      referrer,
      orderDetails,
    });
  }

  return (
    <div className={theme}>
      <ShippingForm onSubmit={handleSubmit} />
    </div>
  );
}
```

- JavaScript에서 함수는 렌더링마다 새로운 객체
- memo가 동작하지 않고 리렌더링

```javascript
const handleSubmit = useCallback(
  (orderDetails) => {
    post('/product/' + productId + '/buy', {
      referrer,
      orderDetails,
    });
  },
  [productId, referrer]
);
```

- useCallback으로 함수 유지
- memo 최적화가 동작

## Memoized 된 함수에서 상태 업데이트

### todos를 기반으로 다음 상태 계산

```javascript
function TodoList() {
  const [todos, setTodos] = useState([]);

  const handleAddTodo = useCallback(
    (text) => {
      const newTodo = { id: nextId++, text };
      setTodos([...todos, newTodo]);
    },
    [todos]
  );
}
```

### 업데이터 함수를 사용해서 의존성 제거 가능

```javascript
function TodoList() {
  const [todos, setTodos] = useState([]);

  const handleAddTodo = useCallback((text) => {
    const newTodo = { id: nextId++, text };
    setTodos((todos) => [...todos, newTodo]);
  }, []); // ✅ todos 의존성 제거
}
```

## Effect가 너무 자주 실행되는 문제

### Effect 안에서 함수를 호출하는 경우

```javascript
function ChatRoom({ roomId }) {
  function createOptions() {
    return {
      serverUrl: 'https://localhost:1234',
      roomId: roomId,
    };
  }

  useEffect(() => {
    const options = createOptions();
    const connection = createConnection(options);
    connection.connect();
  }, [createOptions]); // 🔴 매 렌더마다 변경됨
}
```

### 해결방법

- useCallback 사용
- 함수를 Effect 내부로 이동

# useContext
- useContext는 컴포넌트가 context에 들어있는 값을 쓰고 값이 바뀌면 리렌더링 React Hook
- 컴포넌트 최상위 레벨에서 useContext를 호출하여 context를 읽고 반경에 반응
```javascript
import { useContext } from 'react';

function MyComponent() {
  const theme = useContext(ThemeContext);
  // ...
}
```

## Parameters
- createContext로 생성한 context 객체
- context 자체가 데이터를 담고있지 않음
- 어떤 종류의 데이터를 제공하거나 읽을지만 나타냄

## Returns
- 호출한 컴포넌트의 컴포넌트 트리에서 가장 가까운 ```<SomeContext.Provider>``` 가 전달한 값을 반환
- Provider가 없으면 createContext 에서 지정한 기본값이 반환
  - ```<SomeContext value={undefined}>``` 의 결과값은 ```undefined```
- 반환되는 값은 항상 최신값이며 context값이 바뀌면 react가 자동으로 해당 context를 사용하는 컴포넌트들을 리렌더링

## Caveats
- useContext는 같은 컴포넌트 안에서 반환된 Provider의영향을 받지 않음
- 빌드 시스템이 중복된 모듈을 생성하면 context가 꺠질 수 있음

## Usage
### 트리 깊게 데이터 전달
```javascript
function Button() {
  const theme = useContext(ThemeContext);
  // ...
}
```

- 컴포넌트 최상위 레벨에서 useContext 호출

```javascript
function MyPage() {
  return (
    <ThemeContext value="dark">
      <Form />
    </ThemeContext>
  );
}

function Form() {
  // ... 내부에서 Button을 렌더링 ...
}
```
- Button 컴포넌트(하위 컴포넌트) 또는 부모 컴포넌트를 해당 context provier로 감싼다
- 트리의 깊이에 상관없이 가장 가까운 Provider값을 받는다

### Context로 전달한 데이터 업데이트
- Context값은 state와 사용하면 동적으로 변경 가능
```javascript
function MyPage() {
  const [theme, setTheme] = useState('dark');

  return (
    <ThemeContext value={theme}>
      <Form />
      <Button onClick={() => setTheme('light')}>
        Switch to light theme
      </Button>
    </ThemeContext>
  );
}
```

### Context Overriding
```javascript
<ThemeContext value="dark">
  ...
  <ThemeContext value="light">
    <Footer />
  </ThemeContext>
  ...
</ThemeContext>
```
- provider는 중첩 가능
- 안쪽 provider가 바깥쪽 provider를 덮어씀

### 객채 및 함수 전달시 리렌더링 최적화
```javascript
function MyApp() {
  const [currentUser, setCurrentUser] = useState(null);

  function login(response) {
    storeCredentials(response.credentials);
    setCurrentUser(response.user);
  }

  return (
    <AuthContext value={{ currentUser, login }}>
      <Page />
    </AuthContext>
  );
}
```
- MyApp 리렌더링시 새 객체, 함수 참조가 생성
- context를 사용하는 모든 컴포넌트 리렌더링

### 성능 최적화
```javascript
const login = useCallback((response) => {
  storeCredentials(response.credentials);
  setCurrentUser(response.user);
}, []);

const contextValue = useMemo(() => ({
  currentUser,
  login
}), [currentUser, login]);
```
- useCallback, useMemo 사용

## Troubleshooting
### Provider값이 없을때
1. useContext를 호출한 컴포넌트 아래에 provider를 둔 경우
2. provider를 다른 트리에 둔 경우
3. 빌드 문제로 서로 다른 context 객체를 사용할 경우
