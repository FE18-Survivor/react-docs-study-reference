# useCallback

## Reference

`useCallback` hook 은 함수를 메모이제이션 하는 React Hook이다.

컴포넌트가 리렌더링되어도 의존성 배열이 바뀌지 않으면 캐싱된 동일한 함수를 재사용한다.

`useCallback(fn, dependencies)`

- `fn`: 캐싱할 함수
- `dependencies`: `fn`안에서 사용하는 reactive values

React는 의존성 배열의 값들을 `Object.is` 비교로 이전 렌더와 현재 렌더를 비교한다. 배열 내부 값이 같으면 캐싱된 함수를 반환하고, 다르다면 새로운 함수를 반환 및 캐싱한다. 즉, 의존성이 변하지 않으면 새로운 함수가 생성되지 않는다.

## Usage

### Skipping re-rendering of components

React는 컴포넌트가 렌더링될 때, 그 자식 컴포넌트들도 모두 리렌더링 되는 기본 동작을 가지고있다.

사이즈가 커져서 많은 리렌더링을 하게 되면 렌더링이 느려지는 문제가 발생할 수 있다.

자식 컴포넌트에게 함수를 props로 전달할 때 `useCallback`과 `memo`는 유용하게 사용될 수 있다.

1. 자식 컴포넌트는 `React.memo`로 래핑해서 이전 렌더링과 props가 동일할 때 리렌더링을 skip할 수 있다.

```jsx
import { memo } from "react";

const ShippingForm = memo(function ShippingForm({ onSubmit }) {
  // ...
});
```

2. 함수를 전달할 때 `useCallback`이 없다면 리렌더링 시 매번 새로운 함수를 전달하게 된다.

```jsx
function ProductPage({ productId, referrer, theme }) {
  function handleSubmit(orderDetails) {
    post("/product/" + productId + "/buy", {
      referrer,
      orderDetails,
    });
  }

  return (
    <div className={theme}>
      {/* 자식의 입장에서는 memo를 사용했더라도 props가 매번 달라지기 떄문에 효과 없음 */}
      <ShippingForm onSubmit={handleSubmit} />
    </div>
  );
}
```

3. useCallback을 사용하여 캐싱한다면 리렌더링을 skip할 수 있게 됨

```jsx
function ProductPage({ productId, referrer, theme }) {
  const handleSubmit = useCallback(
    (orderDetails) => {
      post("/product/" + productId + "/buy", {
        referrer,
        orderDetails,
      });
    },
    [productId, referrer]
  );

  return (
    <div className={theme}>
      <ShippingForm onSubmit={handleSubmit} />
    </div>
  );
}
```

> **useMemo vs useCallback**
>
> - `useCallback`: 함수를 기억한다
> - `useMemo`: 함수의 실행 결과 값을 기억한다
>
> **useMemo 예시**
>
> ```jsx
> const getSum = useMemo(() => {
>   return a + b;
> }, [a, b]);
> ```
>
> **useCallback 예시**
>
> ```jsx
> const getSum = useCallback(() => {
>   console.log(a + b);
> }, [a, b]);
> ```

# useContext

컴포넌트에서 Context 값을 읽고, 값이 바뀌면 다시 렌더링되도록 하는 Hook

`const value = useContext(SomeContext)`

## Reference

```jsx
import { useContext } from "react";

function MyComponent() {
  const theme = useContext(ThemeContext);
}
```

### Parameter and Return

- 컴포넌트의 최상위 레벨에서 호출해야함
- `SomeContext`: `createContext`로 만든 context 객체
- 호출한 컴포넌트를 기준으로 트리 위쪽에서 가장 가까운 Provider가 전달한 value를 반환
- 만약 해당 Provider가 없으면 `createContext(defaultValue)`의 defaultValue를 반환

### Caveats

- `useContext`를 호출하는 컴포넌트 위에 Provider가 있어야함
- Provider의 value가 달라지면 `Object.is`로 비교 후 리렌더링 한다.
- `memo`로 매핑하더라도 변경으로 인한 최신 값 전달은 막지 못함

## Usage

- `useContext`를 호출하는 컴포넌트 위쪽에서 가장 가까운 Provider를 찾음
- Provider와 Consumer 사이에 몇 단계의 컴포넌트가 거쳐도 상관없음. `props drilling`을 해결하는 용도로 적합

```jsx
const ThemeContext = createContext(null);

function MyApp() {
  const [theme, setTheme] = useState("dark"); // Context 값은 보통 state와 함께 사용해서 동적으로 변경

  return (
    <ThemeContext value={theme}>
      <Form />
      <button onClick={() => setTheme("light")}>Toggle</button>
    </ThemeContext>
  );
}
```

- Provider가 없을 경우 `defaultValue`인 light 사용
- `undefined`일 경우 undefined를 그대로 전달. Provider가 완전히 없을 때에만 defaultValue가 사용됨

`const ThemeContext = createContext("light")`

- 트리 중간에서 Provider를 다시 선언하면 그 아래부터 새로운 값 적용

```jsx
<ThemeContext value="dark">
  <Page /> // dark
  <ThemeContext value="light">
    <Footer /> // light
  </ThemeContext>
</ThemeContext>
```

- 부모가 렌더링될 때마다 객체가 새로 생성, 모든 consumer가 불필요하게 리렌더링됨

`<Context value={{ user, login }} />`

- 객체/함수는 `useMemo, useCallback`으로 감싸는 것을 권장

```jsx
const value = useMemo(() => ({ user, login }), [user, login]);

<Context value={value} />;
```
