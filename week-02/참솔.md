## [useCallback](https://react.dev/reference/react/useCallback)

- Re-render 사이에 함수 정의를 cache 해 주는 hook
- React compiler를 사용하면 `useCallback`을 직접 사용하지 않아도 compiler가 memoize 해 줌
- `useMemo`와 차이
  - `useMemo`는 전달한 함수가 반환하는 값을 memoize
  - `useCallback`은 전달한 함수 자체를 memoize
- `useCallback`이 유용한 경우
  - 함수가 `memo()`로 감싼 component의 prop으로 전달되는 경우
  - 함수가 다른 hook의 dependency로 사용되는 경우
  - 즉, **`useCallback`은 성능 최적화 목적으로 사용해야 함**
- 아래 방법들을 사용하면 memoization이 필요하지 않을 수도 있음
  - Own state가 변경되는 component를 parent의 `chilren`으로 전달하도록 만들기
  - Local state를 먼저 사용하고, 불필요하게 state를 lift up 하지 않기
  - Rendering logic을 순수하게(pure) 유지하여, 버그 발생 시 memoization을 적용하는 대신 버그를 수정(fix)
  - 불필요하게 state를 갱신하는 Effects를 만들지 않기
  - Effects에서 불필요한 dependency 제거하기

### Reference

- **`useCallback(fn, dependencies)`**
- Parameters
  - `fn` : Cache 하려는 함수 value
    - 함수를 cache 하더라도 React는 매 render 마다 `fn` 함수를 새로 생성함
    - 함수를 생성한 후 `dependencies`에 명시한 reactive values가 변경되지 않았다면, **새로 생성된 함수는 무시하고 cache된 함수를 반환하는 것**
  - `dependencies` : `fn` 내부에서 참조되는 모든 reactive values
    - React linter가 모든 reactive values들을 포함하고 있는지 검증해 줌
    - `Object.is`로 re-render 사이에 값이 변경되었는지 비교
- Returns
  - 최초 render 시 `fn` 함수 반환
  - 이후 render에서,
    - `dependencies`에 명시한 reactive values의 값이 바뀌지 않았다면 저장된 함수 반환
    - Reactive values가 이전 render와 다르다면, 현재 render에서 전달된 새 `fn` 함수 반환
  - 반환되는 함수는 원하는 시점에 직접 호출
- Caveats
  - React는 특별한 이유가 없다면 cached function을 버리지 않음(not throw away)
  - Cached function을 버리는 경우
    - 개발 모드에서 component file을 수정한 경우
    - Component가 initial mount 중에 중단(suspend)된 경우
    - 향후 React가 성능 향상을 위해 cache를 버릴 수 있음

### Usage

- Skipping re-rendering of components
  - Component의 불필요한 re-rendering을 피하기 위해 `memo()` 함수를 사용해서 component를 memoize 할 수 있음
  - `memo()`는 component가 re-render 될 때 모든 props가 동일하다면 cache된 component를 반환하여 re-render를 건너뜀
  - 이 때, prop으로 아래와 같이 함수를 `handleSubmit` 함수를 전달하면 render 될 때마다 함수 prop 값이 변경되므로 `memo()`를 사용하는 의미가 없음
    ```javascript
    function ProductPage({ productId, referrer, theme }) {
      function handleSubmit(orderDetails) {
        post("/product/" + productId + "/buy", {
          referrer,
          orderDetails,
        });
      }
      return (
        <div className={theme}>
          {/* ...ShippingForm will receive the same props and can skip re-rendering */}
          <ShippingForm onSubmit={handleSubmit} />
        </div>
      );
    }
    ```
  - `handleSubmit`을 `useCallback` hook을 통해 cache 하여 re-render 사이에 동일한 함수가 prop으로 전달되도록 개선
    ```javascript
    // Tell React to cache your function between re-renders...
    const handleSubmit = useCallback(
      (orderDetails) => {
        post("/product/" + productId + "/buy", {
          referrer,
          orderDetails,
        });
      },
      [productId, referrer]
    ); // ...so as long as these dependencies don't change...
    ```
- Updating state from a memoized callback
  ```javascript
  function TodoList() {
    const [todos, setTodos] = useState([]);
    const handleAddTodo = useCallback((text) => {
      const newTodo = { id: nextId++, text };
      // setTodos([...todos, newTodo]); // ❌
      setTodos(todos => [...todos, newTodo]); // ✅
    }, []); //  No need for the todos dependency
    // ...
  ```
  - State를 memoized callback에서 변경하는 경우, **state variable 대신 updater 함수로부터 previous state를 사용**
  - `useCallback`의 `dependencies`에 state variable을 명시하지 않아도 되므로 불피료한 re-render 가능성을 줄임
- Preventing an Effect from firing too often
  - Effect 내부에서 호출하는 함수는 `useCallback`으로 cache하여 불필요한 재생성 및 re-render를 방지
    ```javascript
    function ChatRoom({ roomId }) {
      const [message, setMessage] = useState('');
      //
      const createOptions = useCallback(() => {
        return {
          serverUrl: 'https://localhost:1234',
          roomId: roomId
        };
      }, [roomId]); // ✅ Only changes when roomId changes
      //
      useEffect(() => {
        const options = createOptions();
        const connection = createConnection(options);
        connection.connect();
        return () => connection.disconnect();
      }, [createOptions]); // ✅ Only changes when createOptions changes
      // ...
    ```
  - 또는, 함수를 Effect 내부에서 정의하는 것도 방법
    ```javascript
    useEffect(() => {
      function createOptions() {
        // ✅ No need for useCallback or function dependencies!
        return {
          serverUrl: "https://localhost:1234",
          roomId: roomId,
        };
      }
      const options = createOptions();
      const connection = createConnection(options);
      connection.connect();
      return () => connection.disconnect();
    }, [roomId]); // ✅ Only changes when roomId changes
    ```
- Optimizing a custom Hook
  ```javascript
  function useRouter() {
    const { dispatch } = useContext(RouterStateContext);
    const navigate = useCallback((url) => {
      dispatch({ type: 'navigate', url });
    }, [dispatch]);
    // ...
  ```
  - Custom hook을 사용한다면, `useCallback`이 반환한 wrapper 함수를 활용

## [useContext](https://react.dev/reference/react/useContext)

- Component에서 context를 읽고 구독할 수 있게 해 주는 hook

### Reference

- **`useContext(SomeContext)`**
- Parameters
  - `SomeContext` : `createContext`로 생성된 context
    - Context 자체는 값을 갖지 않음
    - Component에서 읽을 수 있는 값의 종류(kind)를 표현
- Returns
  - Context value 반환
  - Context value : render tree에서 **`useContext`를 호출한 component 로부터 가장 가까운 `SomeContext`에 전달된 값**
  - 이러한 provider가 존재하지 않으면 `createContext`에 전달된 `defaultValue`가 반환됨
  - React는 **context value가 변경되면 context value를 읽는 component를 자동으로 re-render**
- Caveats
  - `useContext`와 상호작용하는 `<Context>`는 render tree에서 component보다 상위에 있어야 함
  - React는 `Object.is`를 사용해서 context value 변경을 감지하고, provider부터 context value를 사용하는 모든 children을 re-render
    - `memo()`를 사용한 component도 새 context value를 받을 수 있음
  - Context로 value를 전달하는 것은 context를 제공하기 위해 생성한 `SomeContext`와 component에서 읽는 `SomeContext`가 동일한 객체일 때만 동작 (`===` 비교))

### Usage

#### Passing data deeply into the tree

```javascript
import { createContext, useContext } from "react";

const ThemeContext = createContext(null);

export default function MyApp() {
  return (
    <ThemeContext value="dark">
      <Form />
    </ThemeContext>
  );
}

function Form() {
  return (
    <Panel title="Welcome">
      <Button>Sign up</Button>
      <Button>Log in</Button>
    </Panel>
  );
}

function Panel({ title, children }) {
  const theme = useContext(ThemeContext);
  const className = "panel-" + theme;
  return (
    <section className={className}>
      <h1>{title}</h1>
      {children}
    </section>
  );
}

function Button({ children }) {
  const theme = useContext(ThemeContext);
  const className = "button-" + theme;
  return <button className={className}>{children}</button>;
}
```

- Root component인 `MyApp`에서 `Form`, `Panel` 등 다른 layer를 거쳐 `Button` component까지 값(`theme`)을 전달

#### Updating data passed via context

```javascript
const ThemeContext = createContext(null);

export default function MyApp() {
  const [theme, setTheme] = useState("dark");
  return (
    <ThemeContext value={theme}>
      <Form />
    </ThemeContext>
  );
}

// ...
```

- Context value로 state variable을 전달하면, state가 변경될 때마다 여러 layer를 건너뛰고 특정 component를 re-render 시킬 수 있음

#### Specifying a fallback default value

```javascript
const ThemeContext = createContext("light");
```

- React가 특정 component에서 사용한 context에 대해 tree 상위에서 provider를 찾지 못하는 경우 default value 반환
  - `createContext(defaultValue)`로 context를 생성할 때 설정한 default value
- Provider 없이 `useContext`를 사용하는 component를 render 하거나 test 환경에서 error가 발생하지 않을 수 있음

#### Overriding context for a part of the tree

```javascript
<ThemeContext value="dark">
  ...
  <ThemeContext value="light">
    <Footer />
  </ThemeContext>
  ...
</ThemeContext>
```

- Context provider를 중첩하여 다른 context value를 전달하는 방식으로 context를 재정의 할 수 있음
  - React는 render tree에서 `useContext`를 호출한 component로부터 가장 가까운 provider를 찾기 때문

#### Optimizing re-renders when passing objects and functions

```javascript
import { useCallback, useMemo } from "react";

function MyApp() {
  const [currentUser, setCurrentUser] = useState(null);

  const login = useCallback((response) => {
    storeCredentials(response.credentials);
    setCurrentUser(response.user);
  }, []);

  // Context value가 객체일 때 useMemo를 사용해서 매번 새 객체를 생성하지 않도록 방지
  const contextValue = useMemo(
    () => ({
      currentUser,
      login,
    }),
    [currentUser, login]
  );

  return (
    <AuthContext value={contextValue}>
      <Page />
    </AuthContext>
  );
}
```

- Context value로 객체나 함수를 사용하는 경우, component가 re-render 될 때마다 새 객체가 생성되면서 `useContext`를 호출한 component들을 모두 re-render 시킬 수 있음
- **`useCallback`이나 `useMemo`를 사용해서 성능 최적화**
