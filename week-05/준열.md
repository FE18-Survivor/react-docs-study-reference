# **<a href="https://react.dev/reference/react/useMemo">useMemo</a>**

- 리렌더링 사이에 계산을 **캐싱**할 수 있게 해주는 **React hook**이다.

## **Reference**

- **useMemo(calculateValue, dependencies)**

### **Parameters**

**calculateValue**
- 캐싱하고 싶은 값을 계산하는 함수이다.
- 순수성을 가져야한다.
- 인수를 갖지않아야한다.
- 어떤 유형의 값이든 반환해야한다.
- 의존성 배열이 변경되지 않았다면 같은 값을 반환한다.
- 의존성 배열이 변경되었다면 함수를 호출하여 새로운 값을 반환하고 저장한다.

**calculateValue**
- props, state 등 컴포넌트 내부에 선언된 변수, 함수가 모두 포함된다. 

### **Returns**

- 초기 렌더링에는 인수 없이 호출한 함수의 결과를 반환한다.
- 그 이후에는 의존성 배열의 변경사항을 기준으로 결과를 반환한다.

### **Caveats**

- 최상위 레벨 OR 훅 내부에서만 호출 가능
- 조건, 반복 안에서는 호출할 수 없다.
- Strict 모드에서는 두 번 실행함 ( 순수성 보장 ) -> 호출 중 하나는 무시 됨
- React는 특별한 경우 아니면 캐싱된 값을 버리지않음 -> useMemo는 성능최적화 용도로 사용하자

## Usage

### Skipping expensive recalculations

- **useMemo**를 이용해 큰 배열을 필터링하거나 무거운 계산을 캐싱 즉, 메모이제이션 하여 의존성 배열에 변화가 없다면 건너뛸 수 있다.

### Skipping re-rendering of components 

```javascript
import { useMemo, memo } from 'react';

// 1. 자식 컴포넌트를 memo로 감싸 'props가 같으면 재렌더링 안 함' 설정
const List = memo(function List({ items }) {
  console.log('List 렌더링...');
  return <ul>{items.map(item => <li key={item.id}>{item.text}</li>)}</ul>;
});

export default function TodoList({ todos, tab, theme }) {
  // 2. 테마(theme)만 바뀔 때 visibleTodos가 새로 생성되는 것을 방지
  // useMemo를 안 쓰면 filterTodos는 매번 '새 배열'을 만들어내어 List가 재렌더링됨
  const visibleTodos = useMemo(
    () => filterTodos(todos, tab), 
    [todos, tab] // 오직 todos나 tab이 바뀔 때만 새 배열을 만듦
  );

  return (
    <div className={theme}>
      {/* 3. visibleTodos의 참조값이 동일하므로, theme가 바뀌어도 List는 재렌더링되지 않음 */}
      <List items={visibleTodos} />
    </div>
  );
}
```

- 기본적으로 부모 컴포넌트가 리렌더링되면 모든 자식 컴포넌트도 재귀적으로 리렌더링된다.

- 그렇기에 **memo**와 **useMemo**를 조합하면, 데이터가 변하지 않았을 때 자식의 렌더링을 완벽하게 차단할 수 있다.

### Preventing an Effect from firing too often

```javascript
function ChatRoom({ roomId }) {
  // 문제: 컴포넌트가 재렌더링될 때마다 새로운 객체가 생성됨
  // 이 때문에 useEffect는 options가 바뀌었다고 판단해 매번 채팅방에 재접속함
  // const options = { serverUrl: 'https://localhost:1234', roomId: roomId };

  // 해결: useMemo로 객체 참조를 고정
  const options = useMemo(() => ({
    serverUrl: 'https://localhost:1234',
    roomId: roomId
  }), [roomId]); // 오직 roomId가 바뀔 때만 객체가 새로 생성됨

  useEffect(() => {
    const connection = createConnection(options);
    connection.connect();
    return () => connection.disconnect();
  }, [options]); // 이제 options는 roomId가 바뀔 때만 변경됨
}
```

- useEffect의 의존성 배열에 객체나 배열을 넣으면, 리액트는 렌더링 때마다 **이 객체가 이전과 같은가?** 를 체크한다. 

- 하지만 객체 리터럴은 매번 새로운 참조를 만들기 때문에 Effect가 매번 실행되는 문제가 생긴다.

### Memoizing a dependency of another Hook

```javascript
function SearchResults({ query }) {
  // 1. query가 같으면 동일한 객체 참조 유지
  const searchOptions = useMemo(() => ({
    query,
    limit: 10
  }), [query]);

  // 2. searchOptions의 참조가 고정되었으므로, 불필요한 API 재호출 방지
  const results = useMemo(() => {
    return fetchData(searchOptions);
  }, [searchOptions]); // searchOptions가 메모화되지 않았다면 매번 실행됨

  return <List items={results} />;
}
```

- 하나의 useMemo 계산 결과가 또 다른 **useMemo**나 **다른 Hook의 의존성**으로 사용될 때, 중간 단계의 값을 메모화하여 연쇄적인 계산을 막는다.

### Memoizing a function

```javascript
export default function Page({ productId, referrer }) {
  // 렌더링 때마다 새로운 함수 생성 -> 자식(Button)은 매번 재렌더링됨
  // const handleSubmit = (orderDetails) => {
  //   post('/product/' + productId + '/buy', { referrer, orderDetails });
  // };

  // useMemo로 함수 자체를 반환하여 참조 유지
  const handleSubmit = useMemo(() => {
    return (orderDetails) => {
      post('/product/' + productId + '/buy', { referrer, orderDetails });
    };
  }, [productId, referrer]);

  return <Button onSubmit={handleSubmit} />;
}
```

- 함수도 자바스크립트에서는 객체의 일종이다. 

- 렌더링 때마다 선언되는 함수는 매번 새로운 참조를 가지므로, 이를 memo된 자식 컴포넌트에 넘길 때 문제가 된다.

- **useMemo**로 함수를 반환하는 패턴은 매우 흔하다. React에서는 이러한 패턴을 더 쉽게 해주는 hook을 만들었는데, 그게 바로 **useCallback** 이다. 

<br />

> [!WARNING]
> - 항상 메모리 비용을 계산하자. 과도한 메모이제이션은 메모리 점유율을 높힌다.
> - 의존성 배열 누락을 조심하자. 오래된 값을 참조하는 버그를 발생 시킬 수 있다.
