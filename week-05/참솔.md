# Week 05

## [useMemo](https://react.dev/reference/react/useMemo)

- Re-render 사이에 계산 결과를 cache 해 주는 hook
- React compiler가 values 및 functions를 자동으로 memoize 해 주기 떄문에 `useMemo`를 직접 호출할 일이 줄어듦

### Reference

- `useMemo(calculateValue, dependencies)`
- Parameters
  - `calculateValue` : cache 하려는 value를 계산하는 함수
    - Parameter가 없는 순수 함수여야 함
  - `dependencies` : `calculateValue` 함수 안에서 사용되는 reactive values
- Returns : `calculateValue`를 호출해서 반환되는 값 또는 memoize 된 값
- Caveats
  - Strict mode에서 두 번 호출될 수 있음
    - Accidental impurities를 개발 환경에서 발견하기 위함
    - `calculateValue` 함수가 순수하다면 logic에 영향을 주지 않을 것
  - React는 특별한 이유가 없다면 cached value를 버리지(throw away) 않음
    - Cached value를 버리는 경우
      - 개발 환경에서 component file을 수정했을 때
      - 개발 및 상용 환경에서 component의 initial mount가 중단될 때
    - 성능 최적화 목적이 아니라면 state variable이나 ref를 사용하는게 더 적합함

### Usage

#### Skipping expensive recalculations (memoization)

```javascript
function TodoList({ todos, tab, theme }) {
  const visibleTodos = useMemo(() => filterTodos(todos, tab), [todos, tab]);
  // ...
}
```

- 크기가 큰 배열을 filtering 또는 transforming 하거나 복잡한 연산을 하는 경우, data가 변경되지 않았다면 연산을 건너뛰고 이전에 계산된 값을 재사용
- `useMemo`는 성능 최적화를 위해서만 사용해야 함 (코드가 `useMemo` 없이 동작하지 않는다면 이것부터 고칠 것)
- Expensive calculation을 판단하는 방법
  - 일반적인 연산 작업은 무겁지 않음
  - 실행하려는 코드 전후에 `console.time()`을 사용해서 실행 시간을 직접 계산해 볼 수 있음
    ```javascript
    console.time("filter array");
    const visibleTodos = filterTodos(todos, tab);
    console.timeEnd("filter array");
    ```
- 개발 machine은 실제 사용자 환경보다 더 좋기 때문에, chrome의 CPU throttling 옵션을 활용해서 테스트 해보면 좋음
- 개발 환경에서 성능을 측정하면 Strict Mode 등에 의해 결과가 정확하지 않으므로 production으로 빌드해서 테스트 해야 함
- `useMemo`를 언제 사용하면 좋을까?
  - Page 또는 큰 section 전체를 교체하는 interaction이 대부분이라면 `useMemo`가 필요하지 않음
  - Editor를 만들거나 작은 단위의 interactions를 다룰 때 유용함
  - `calculateValue` 함수가 느린데 `dependencies`는 자주 바뀌지 않는 경우 유용
  - Memoized value를 `memo`로 감싼 component의 prop으로 전달해서 component re-rendering를 건너뛸 수 있음
  - Memoized value를 다른 `useMemo`나 `useEffect`의 `dependencies`로 전달해서 re-calculation을 건너뛸 수 있음
  - **이 외의 상황에서는 코드만 읽기 힘들어질 뿐 `useMemo`를 사용하는 이점이 없음**
- Memoization이 필요하지 않게 만드는 원칙들
  - 시각적으로 component가 다른 component를 감싸고 있다면 JSX를 `children`으로 받기
  - Local state를 우선 사용하고 꼭 필요한 경우에만 state를 lift up 하기
  - Rendering logic을 순수하게 만들기 (component가 re-render 되어도 시각적으로 변화가 없도록 우선 수정할 것)
  - 불필요하게 state를 변경하는 Effect를 사용하지 않기
  - Effects에서 불필요한 dependencies 제거하기
  - **이 원칙들을 적용해도 성능 문제가 발생한다면 memoization을 적용하기**

#### Skipping re-renering of components

- `useMemo`는 child component의 re-rendering 성능을 최적화 하는 데에 활용할 수 있음
- Component가 re-render 되면 모든 children을 재귀적으로(recursively) re-render 함
- 성능에 영향을 미치는 child component를 `memo()` 함수로 감싸서 정의하고,
  ```javascript
  const List = memo(function List({ items }) {
    // ...
  });
  ```
- 이 component의 prop으로 `useMemo` 반환값을 전달
  ```javascript
  export default function TodoList({ todos, tab, theme }) {
    const visibleTodos = useMemo(() => filterTodos(todos, tab), [todos, tab]);
    return (
      <div className={theme}>
        {/* ...List will receive the same props and can skip re-rendering */}
        <List items={visibleTodos} />
      </div>
    );
  }
  ```
- 이렇게 하면 `useMemo`가 이전 render와 같은 값을 반환할 때 `List` component도 re-rendering을 skip 할 수 있음
- JSX도 JavaScript 객체이므로, component를 `memo()` 함수로 감싸서 정의하는 대신 JSX node 자체를 `useMemo`로 감쌀 수도 있음

  ```javascript
  export default function TodoList({ todos, tab, theme }) {
    const visibleTodos = useMemo(() => filterTodos(todos, tab), [todos, tab]);
    const children = useMemo(
      () => <List items={visibleTodos} />,
      [visibleTodos],
    );
    return <div className={theme}>{children}</div>;
  }
  ```

  - `useMemo`로 JSX를 memoize 하는 것은 선택적으로 적용할 수 없어서 불편하기 때문에, 일반적으로 component 함수를 `memo()`로 감싸는 방식을 사용함

#### Preventing an Effect from firing too often

- 함수 body에서 선언하는 값을 Effect 내부에서 사용하면, component가 re-render 될 때마다 값이 변경되므로 Effect가 게속 재실행 됨

  ```javascript
  const options = {
    serverUrl: "https://localhost:1234",
    roomId: roomId,
  };

  useEffect(() => {
    const connection = createConnection(options);
    connection.connect();
    return () => connection.disconnect();
  }, [options]); // 🔴 Problem: This dependency changes on every render
  ```

- Effect 내부에서 사용되는 reactive value 생성 시 `useMemo`를 사용하면 re-render 사이에 값이 변경되지 않으므로 불필요한 Effect 재실행을 막을 수 있음

  ```javascript
  const options = useMemo(() => {
    return {
      serverUrl: "https://localhost:1234",
      roomId: roomId,
    };
  }, [roomId]); // ✅ Only changes when roomId changes

  useEffect(() => {
    const connection = createConnection(options);
    connection.connect();
    return () => connection.disconnect();
  }, [options]); // ✅ Only changes when options changes
  ```

- 단, React가 특별한 이유로 `useMemo`로 cache한 값을 버릴 수 있기 때문에 logic을 `useMemo`로 감싸는 것보다 Effect 내부로 옮기는 것이 더 좋은 방법

  ```javascript
  useEffect(() => {
    const options = {
      // ✅ No need for useMemo or object dependencies!
      serverUrl: "https://localhost:1234",
      roomId: roomId,
    };

    const connection = createConnection(options);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]); // ✅ Only changes when roomId changes
  ```

#### Memoizing a function

- 함수를 memoize 할 때는 `useMemo` 대신 `useCallback`을 사용하는게 더 간결함

  ```javascript
  const handleSubmit = useMemo(() => {
    return (orderDetails) => {
      post("/product/" + productId + "/buy", {
        referrer,
        orderDetails,
      });
    };
  }, [productId, referrer]);

  const handleSubmit = useCallback(
    (orderDetails) => {
      post("/product/" + productId + "/buy", {
        referrer,
        orderDetails,
      });
    },
    [productId, referrer],
  );
  ```
